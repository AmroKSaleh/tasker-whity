# Flows: REFINE not rebuild — the redefinition never needed a new model (TDE-816/TDE-792, 2026-08-04)

_KB entry · source: agent · READ-ONLY mirror (edit via create_kb_entry/update_kb_entry over MCP)._

The rebuild-or-refine question that blocked TDE-816 is CLOSED: **refine**. Do not re-open it, and do not treat the Flow redefinition (TDE-792) as license to rebuild the flows feature or its page.

**Why.** The decision was effectively made by action before anyone wrote it down. Three changes had already landed against the new definition without needing a new data model: TDE-808 shipped a directive, TDE-813 reworked the trust badges to stop overclaiming, TDE-820 made contracts non-blocking. The model absorbed the redefinition intact. TDE-792 then closed 2026-07-30 by writing the canonical KB entry and re-judging parked tasks keep/reshape — never cut-and-rebuild.

**The generalizable insight, worth reusing whenever a definition changes under existing code:** ask whether the parts that must change are the same parts that carry the debt. On the Flows page they were not, and that settled it. FlowsPage.jsx is 660 lines with ~430 in one `FlowDetail` component — but that bulk is five inline CRUD mutations (duplicate, delete, rename, short-id, save-as-template), i.e. flow *management*, which the redefinition does not touch. Everything the new definition actually wants is small or additive: gate the graph on `edgeCount > 0` (already computed), add an exceptions block to the existing right-hand pane, fix a two-line progress denominator, emphasize the terminal step inside a 190-line component. A big file is not automatically a rebuild candidate — locate the change before sizing it.

**Corollary that saved scope:** the adjacent-refactor temptation was declined. Splitting FlowDetail is real debt but inert (nothing in the redefinition touches it), and TDE-816 sits on the Phase-1 launch critical path, so it was filed as its own low-priority Core App task instead of bundled.

**Stale-analysis warning, now the third instance of this pattern in TDE.** TDE-816's design analysis (2026-07-28) states FlowGraph occupies a 320px top band with the step list buried. Untrue as of 2026-08-04: FlowsPage.jsx lines 503-556 already render a two-pane split with a right-hand pane commented "Action Center / Cockpit" containing LiveStatusBanner + FlowStepList. Someone built the cockpit pane and the analysis was never updated. The surviving critique is that the graph still holds the larger non-collapsible pane — weighting, not burial. Prior instances: stale task records (TDE-263, pull_google_task, TDE-780) and a stale summary (TDE-790's blocker list). **Rule: any design analysis or blocker note older than a few days gets re-verified against the code before it is acted on.** The cost of not doing this is redesigning something that was already fixed.

**What is genuinely still missing on the page (verified in code, not asserted):** exception surfacing. LiveStatusBanner reports COMPLETE / IN PROGRESS / WAITING and mentions contracts needing blessing — that is status. Nothing renders "step 4 failed its check, here is the observed value." Per Q7 (TDE-799) this is the whole point of the human's relationship to a flow, and the MCP side already ships it via get_flow_exceptions (TDE-382), so the web side should consume that same shape rather than compute its own and drift.
