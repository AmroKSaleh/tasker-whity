name_flow stamps step numbers at flow-creation time and they go STALE if the DAG is edited afterward. Found while building the BKT "Launch keylife.tech" flow: a pre-existing edge made a node (Home) cyclic, so it got a high step number; after the cyclic edge was removed the DAG was correct (verified via get_task_connections + run_flow "Requires" lines), but get_flow_order and run_flow still rendered the creation-time step number, showing Home after the build gate it actually precedes.

Needed: a way to recompute/renumber a flow's step order on demand after edges change (or auto-recompute on every set_task_input/set_task_output change). RELATED GAP: there is currently no delete_flow / reset-flow tool, so a mis-numbered or duplicate flow can't be removed — consider adding that too. Without these, the only safe fix today is editing edges and living with stale display numbers.
