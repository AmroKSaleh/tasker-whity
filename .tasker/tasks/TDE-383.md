From Linear: users steer a working agent mid-session ("prompted" events push the user's message into the agent's context), and agents get their own notification inbox via AppUserNotification webhooks (mentions, assignments, status changes) — the agent has the same attention surface an employee has. Both are PUSH mechanisms; Tasker is pull-based (MCP client in the user's own session), so we translate, not copy.

Build (MCP-only — NO app-wide inbox UI; that decision stays locked, Conductor remains per-connector): (a) pending guidance — a human attaches a steering note to a task from the inspector; the next get_task on it surfaces the note prominently and marks it consumed; (b) get_my_attention MCP tool — one cross-task pull: tasks awaiting review verdicts, pending guidance, stale in_progress, urgent items — designed as the agent's first move after __init_tasker_session.

Wedge: attention that persists across sessions — the human leaves direction while the agent is away; the agent picks it up next session without re-prompting.

## Build spec — locked 2026-07-11 (my recommendation)
MCP-only — NO app-wide inbox (that decision stays locked; Conductor stays per-connector). Two parts:
(a) **Pending guidance:** human attaches a steering note to a task from the inspector; the next get_task surfaces it LOUD (like relay_context) and marks it consumed. Storage: a `task_guidance` row (task_id, body, created_at, consumed_at) or a column pair on tasks.
(b) **get_my_attention** MCP tool — one cross-task pull returning: tasks awaiting review verdicts, unconsumed pending guidance, stale in_progress, and overdue/urgent. Wire it into the __init playbook as the agent's recommended FIRST move after __init_tasker_session.
