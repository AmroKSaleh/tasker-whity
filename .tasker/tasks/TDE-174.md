What it means: put the Tasker codebase under git + GitHub version control. Right now the project is NOT a git repository (confirmed: "Is a git repository: false") and the only safety net is manual zip backups to Google Drive — i.e. no version control, no diff history, no real revert. That's dangerous given the volume of live changes (and it bit us once already — a memory file had stray corruption with no way to revert).

Why it's foundational: it's the safety net for ALL future work, and it's the substrate for the whole repo-native direction ([[design_repo_native_pivot]]: git push/pull is the sync mechanism, no API). Everything else builds on this.

Scope to define: git init the project, set up .gitignore (node_modules, dist, env/secrets), create the GitHub repo, initial commit + push, establish a commit workflow.
