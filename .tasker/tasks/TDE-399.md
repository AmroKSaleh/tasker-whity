Split out of TDE-377 (outbound webhooks), which shipped & verified LIVE for task + review events (task.updated, task.completed, review.submitted) — a real signed POST landed at a webhook.site endpoint via the pg_cron drain. Two deferred pieces:

1. FLOW EVENTS (the reason for the split): emit `flow.step_unblocked` when an upstream task's completion unblocks a downstream flow task — the "flow step ready → wake an executor" trigger. Non-trivial because there is no single choke point: completion cascades through I/O edges (see unmetSourcesDeep / contract_gate). Approach: in complete_task, after marking done, find downstream consumers (tasks whose input edges reference this task) that just became fully-unblocked and emit one flow.step_unblocked per newly-ready task. Reuse emitWebhook() (already in the MCP fn). Add 'flow.step_unblocked' to the Settings UI event list (WebhooksSection.jsx EVENTS array).

2. DELIVERY HARDENING (nice-to-have, not blocking): the retry ladder (1min/1hr/6hr) + auto-disable-after-20-failures are code-verified (deno-checked) but never RUNTIME-observed. Exercise them against a deliberately failing endpoint (e.g. httpstat.us/500). Also do a one-time exact HMAC-value check: recompute HMAC-SHA256(body, endpoint_secret) and confirm it equals the X-Tasker-Signature header (the live test confirmed the header is present + well-formed, not that the value matches).

Cold-reader pointers: emitWebhook() + the three wired events are in V2/supabase/functions/mcp/index.ts; the drain is V2/supabase/functions/webhook-dispatch/index.ts; schema in migration 20260713120000; cron+vault-auth in 20260713121000 (see KB "Webhooks: cron→edge-function auth via DB-generated Vault secret").
