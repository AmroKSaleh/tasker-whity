From Linear: agents are named workspace citizens (OAuth actor=app) — every mutation is attributed to the agent ("Name via App"), agents are @mentionable/assignable, and assignment to an agent sets a DELEGATE field, not assignee: "the human teammate remains responsible for its completion." Their line: delegate issues, not accountability. Agents are explicitly never billable seats.

Build: an actor/provenance field threaded through MCP writes (which agent/client did what — e.g. "Claude Code", "Gemini"), rendered as "via agent" on task events, notes, reviews in the inspector; a delegated_to field on tasks distinct from ownership — the human always owns the gate; filter/group by agent in views. Our positioning says state "persists across sessions, agents, and people" but today we can't attribute which agent did what — this makes the claim true in the data.

Feeds TDE-363 (Tasker Agents — this is its identity layer) and TDE-328 (members + relay routing). Pricing principle to keep forever: agents never cost seats.

## Build spec — locked 2026-07-11 (my recommendation, per "execute with what you recommend")
- The `actor` column ALREADY EXISTS on agent_sessions (created in TDE-374) — this task populates it fully + threads actor everywhere.
- RECOMMENDED provenance model: **token-derived actor, NOT client-supplied**. Add `agent_label` to user_api_keys; resolveApiKey returns {userId, actor}; write actor into ledger entries + a task-events log. Rationale: an actor the agent passes itself can be spoofed; an actor bound to the API key is trustworthy provenance (matches Linear's OAuth actor=app). A client-supplied `actor` arg (already accepted by append_session_activity) is a convenience fallback only.
- `delegated_to` on tasks: SEPARATE column from user_id. Human ALWAYS stays owner (user_id) and owns the gate/completion; delegated_to is who is doing it. Render "delegated to X"; filter/group by actor in views.
- Pricing invariant to keep forever: agents never consume a billing seat.
Build order: agent_label on keys → resolveApiKey returns actor → backfill actor into ledger writes → delegated_to + inspector "via {actor}" attribution + agent filter. Depends on TDE-374 shipping first (shares the session substrate).
