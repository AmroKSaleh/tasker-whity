Add revision-loop support to Flows — the multi-step auto-correction cascade that sits ON TOP of the contract foundation (TDE-137). See KB "Flow's Messaging Angle" for the strategic framing.

## Context / reframe (2026-06-04)
Flows are positioned as the human-owned CONTRACT + visual + reuse layer over agent work, NOT as orchestration (the platform commoditizes that). TDE-137 builds the foundation: author contracts, validate a single handoff, store feedback, reopen the failed task. THIS task (156) adds the automated revision LOOP across the flow.

## What 156 does
When a handoff fails its contract, route the feedback back upstream and have the agent regenerate, then re-validate — looping until it passes or hits a guard. This is the "feedback routes back to upstream task for output regeneration" behavior.

## Locked guardrails (decided 2026-06-04)
- SUPERVISED AUTOPILOT, not fire-and-forget.
- RETRY CAP: regenerate up to 3 times, then pause and ask the human.
- REOPEN TARGET: reopen at most 2 tasks upstream; if the contract still can't be satisfied there, STOP and ask for human intervention (do not auto-cascade further back).
- Validation/regeneration judgment runs on the dev's own Claude via MCP (dev/MCP-exclusive, no Tasker inference cost). Watch token cost — a loop that regenerates burns the dev's tokens, hence the hard caps.

## Depends on
TDE-137 (contract + single-handoff validate + feedback + reopen). Don't start 156 until 137's foundation exists.
