THE adoption unlock for the dev/lens wedge.

Insight: forcing our own .tasker/ format is "be the store" in disguise — it competes with FREE native stores (Claude Code native Tasks in ~/.claude/tasks; GitHub Spec Kit ~90k stars, tasks.md). Devs won't adopt a competing task store.

Instead: `npx tasker` should DETECT and READ whatever task state already exists in the repo — Spec Kit tasks.md, Claude Code native task lists, plain markdown checklists — and render the Blueprint/board over it with ZERO setup. Meet them where they are.

.tasker/ then becomes the OPTIONAL rich upgrade for those who want the relational model flat formats can't express (sections, groups, flows, I/O dependencies, milestones).

Start with detecting + importing Spec Kit tasks.md (biggest, fastest-growing). Note: parser already has parseTaskerContent() stubbed for the GitHub Contents API (future) — reuse that shape.
