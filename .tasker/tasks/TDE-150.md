The app-side trigger for GitHub write-back. The MCP/agent path is already built & deployed (TDE-148): github_push_task and github_push_project push title + body + open/closed state to the linked issue, and create a new issue for unlinked tasks. This task is the UI equivalent so non-CC users can push from the app.

Scope:
- A "Push to GitHub" action in the project UI (e.g. ProjectHeader, near the existing Export / sync controls) — only shown when the project has a linked github_repo.
- Single-task push from the task detail panel, and/or a project-level "push all" with a confirm step.
- Reuse V2/app/src/lib/github.js — its githubFetch already supports write methods (method/body via options). Mirror the MCP logic in pushTaskToGitHub: PATCH /repos/{repo}/issues/{number} { title, body, state } for linked tasks; POST /repos/{repo}/issues for unlinked, then store github_issue_number; new issues created open, close afterward if task is done.
- ALWAYS confirm before pushing (project Instruction Set rule: "confirm before pushing to any remote").

Caveat to handle: token must have issues WRITE scope. PAT with "repo" scope works; GitHub-OAuth-login tokens (TDE-75/91) may be read-only → surface a clear error if push returns 403.
