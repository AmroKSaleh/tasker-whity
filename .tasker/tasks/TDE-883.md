Requested by the owner 2026-08-08 after hitting all three in one sitting.

THREE CHANGES

1. DELETE ORGANIZATIONS — currently impossible. app/src/lib/organizations.js lines 6-7 say it outright: "Deletion is intentionally omitted for v1 (heavy + would orphan org projects) — add later behind an explicit, well-guarded flow." Only createOrganization and renameOrganization exist. The guard problem is real: an org owns environments, which own projects, so a naive delete orphans real work.

2. UNNAMED ORG SHOWS AS "n/a" — the owner reports an organization they did not name. Note handleCreateOrg (OrganizationsPage) already rejects a blank name with `if (!n) return`, so the normal path cannot produce one; whatever exists predates that guard or came in another way. A display fallback is more robust than a one-off data fix because it also covers anything that slips through later.

3. HIDE EMPTY ORGS FROM THE ENVIRONMENT SWITCHER — the dropdown on the projects page (EnvironmentSwitcher.jsx, rendered from HomePage). It currently hides an org group only when it has no ENVIRONMENTS (line 25: `.filter(g => g.envs.length)`). The owner wants it hidden when it has no PROJECTS — an org full of empty environments is still noise. Requires passing projects into the component, which it does not currently receive.

CONTEXT ON THE CONFUSION THAT PRODUCED THIS
"Personal" is NOT an organization — EnvironmentsPage.jsx line 14 hardcodes it as a pseudo-owner `{ id: null, name: 'Personal' }` meaning org_id IS NULL. It renders as a peer tab beside real orgs, which reads as though it were one; the owner expected to find it on the Organizations page and could not. Worth its own fix (relabel, or make Personal a real org in Phase 2) but that is NOT part of this task.

UNRESOLVED AT FILING: the switcher renders group headings from `org.name`, and personal envs render BEFORE the org groups. The owner's screenshot shows a second "PERSONAL" heading AFTER the org groups, containing environments "Tasker" and "Abaq". That can only happen if an organization is literally named "Personal" — not if it is unnamed. Confirm which before doing any one-off data rename.
