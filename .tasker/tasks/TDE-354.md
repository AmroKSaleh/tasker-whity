First build step of the Environments feature (from TDE-308, decided 2026-07-02). Hierarchy: Tasker → Environments → Projects → Sections → Tasks. Environments partition a single user's contexts (Personal / Work / Learning). SINGLE-USER ONLY — no team membership, no sharing.

Deliverable: one timestamped migration in V2/supabase/migrations/ (follow the existing YYYYMMDDHHMMSS_*.sql naming):
1. `environments` table: id uuid PK, user_id (FK auth.users), name text, sort_order int, created_at. RLS policies scoped to user_id, same pattern as projects.
2. `projects.environment_id` uuid FK → environments, nullable during migration.
3. Backfill: create one "Default" Environment per existing user, assign all their projects to it. After backfill the app treats environment_id as required for new projects (enforce in app/MCP layer, keep column nullable for safety).
4. `user_settings.active_environment_id` uuid nullable — the server-owned active-Environment pointer (user_settings already holds default_project_id, so this is the established home for per-user pointers; see V2/supabase/functions/mcp/index.ts:105 for how default_project_id is read).

Decisions already made (do not reopen): exclusive switching (one Environment visible at a time); Today/Focus stays CROSS-environment; web app owns the active pointer, MCP receives environment_id explicitly.

Gotchas: check KB entry "Deployment: remote migration history drifts — repair before db push". Migrations dir also contains legacy un-timestamped files — ignore them, use the timestamped convention.
