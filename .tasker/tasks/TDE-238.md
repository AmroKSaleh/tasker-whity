There is no clean way to rename an existing flow via the MCP. Workaround today is calling name_flow again with the full task_ids list, which DOES update the flow's name field, but it is clunky (requires re-passing every task ID) and not discoverable.

Add a dedicated tool, e.g. rename_flow(flow_id, new_name) — update the flow's name without re-supplying its task list.

RELATED UX BUG worth checking at the same time: the Flows page appears to label each flow by its FIRST STEP's task text rather than the flow's name field. Repro (2026-06-10, WCC): created "Content Creation Flow", renamed to "Content Funnel" via name_flow (data confirmed updated), but the Flows page still displayed "Ideation — select topic…" (the first task). So even with a rename tool, the display won't reflect the flow name until the page reads the name field. Fix both: the rename tool AND the flows-page label source.

Context: surfaced while building the "Content Funnel" flow in WCC. See also the existing flow renumber / delete_flow gap task in this section.

--- CORRECTION + frontend half fixed — 2026-07-17 (later) ---
Earlier this task was closed believing the frontend label bug was "already fixed" (FlowsPage.jsx renders {flow.name}). That was WRONG — a user test caught it still live: renamed flow TDE-F2 to "Local Test" (DB confirmed correct via list_flows), but the Flows page still showed "Local Mode: .tasker/ format…" (the first task's text).

ROOT CAUSE (not FlowsPage.jsx — it renders flow.name correctly; the bug was upstream in the data assembly): hooks/useFlows.js built each flow object with `name: f.autoName` (auto-detected from the first task) and its flows query did not even SELECT `name`. So DB renames were thrown away at render time.

FIX (V2/app/src/hooks/useFlows.js, 2 edits): (1) add `name` to the flows select; (2) `name: flowRec?.name || f.autoName` — human-set name for named flows, auto-name fallback for unnamed detected flows.
SHIP: vite build clean, deployed to Netlify (smarttasksxdd). Commit ba96bac on branch tde-238-rename-flow-discoverability. VERIFIED LIVE by the user — TDE-F2 now displays "Local Test" correctly.
Lesson: reading the render component wasn't enough; the name was overwritten in the assembling hook. Verify UI claims against actual render, not just the leaf component.
