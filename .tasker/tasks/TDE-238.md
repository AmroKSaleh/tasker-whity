There is no clean way to rename an existing flow via the MCP. Workaround today is calling name_flow again with the full task_ids list, which DOES update the flow's name field, but it is clunky (requires re-passing every task ID) and not discoverable.

Add a dedicated tool, e.g. rename_flow(flow_id, new_name) — update the flow's name without re-supplying its task list.

RELATED UX BUG worth checking at the same time: the Flows page appears to label each flow by its FIRST STEP's task text rather than the flow's name field. Repro (2026-06-10, WCC): created "Content Creation Flow", renamed to "Content Funnel" via name_flow (data confirmed updated), but the Flows page still displayed "Ideation — select topic…" (the first task). So even with a rename tool, the display won't reflect the flow name until the page reads the name field. Fix both: the rename tool AND the flows-page label source.

Context: surfaced while building the "Content Funnel" flow in WCC. See also the existing flow renumber / delete_flow gap task in this section.
