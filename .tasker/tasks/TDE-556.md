RE-SCOPED 2026-07-28. This task was previously "[STEAL] Query surface over the I/O + flow graph", the canonical home for a WIQL-style query engine with three merged facets. On inspection of the actual code the packaging was wrong — the three facets had different dependencies and one of them was a write-path fix, not a query feature — so it was dissolved into its proper homes and this task retains only the third facet.

WHERE THE THREE FACETS WENT:
- Facet 1, the query engine + the DSL-vs-param-object decision → folded into **TDE-378** (MCP tool-surface diet), whose item (d) "shared filter grammar" was the same decision from the token-economy side. DECIDED THERE: param-object, not a DSL — because as a params grammar one query tool can SUBSUME several of the 34 existing list_*/get_* tools (of 137 total), making it TDE-378's enabler rather than tool #138.
- Facet 2, the queryable audit trail (originally merged in from TDE-557) → extracted to **TDE-818** (Durable gate history). Its premise — "we have adjacent pieces, this is consolidation not net-new" — was verified and found FALSE: get_flow_audit (index.ts:6148) is a snapshot renderer over mutable JSONB, not a log; confirm_contract, submit_task_review and submit_validation_result all overwrite rather than record. You cannot query history that was never written, so it is a write-path fix that must precede any query over it.
- Facet 3, saved views → THIS TASK, unchanged in substance (see the merged TDE-786 note below).

WHAT REMAINS HERE (mined from Plane's saved custom Views): do NOT build a standalone "Views" feature or a second filtering system. Human "saved views" = a thin wrapper that persists a named query and renders it in the web inspector, over the SAME grammar agents use via MCP. One engine, two faces: agents query programmatically, humans save/name queries as views. The web app is the human-inspector surface, which is on-wedge.

WHY NOT NOW: this is purely a convenience face and it is downstream of both TDE-378 (the grammar it wraps) and, for any history-based view, TDE-818 (the history it would read). There is nothing to wrap yet. Dropped high → low accordingly. Build it after TDE-378 ships item (d), and consider whether the persist-and-name affordance is small enough to just ship inside TDE-378 rather than as its own task — if it is, close this as covered.
