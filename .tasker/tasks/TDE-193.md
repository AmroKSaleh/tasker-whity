Idea (added 2026-06-05): new projects could come with a sensible DEFAULT Instruction Set instead of starting blank — and/or a small library of IS templates the user can apply/adapt at creation.

Context: the IS (Instruction Set) is the per-project set of directives that govern how work is done. Stored via create_is_entry / get_project_is, auto-injected into every get_task response. Today a new project has no IS until one is authored, so early sessions lack project guidance.

———————————
✅ DECISION + IMPLEMENTATION (2026-06-13):
DECISION (user): "Baseline + AI-proposed" — auto-apply a universal baseline IS on creation AND have the AI propose stack-specific additions during conversational creation for the user to confirm. Parity approach: DB trigger (covers all creation paths from one place).

IMPLEMENTED (code complete, not yet deployed/applied):
1. DB trigger — NEW migration V2/supabase/migrations/20260613120000_seed_baseline_instruction_set.sql. seed_baseline_instructions() (SECURITY DEFINER, search_path=public) + AFTER INSERT trigger on `projects` seeds 2 baseline IS rows on EVERY creation path (MCP, manual UI, AI gen, GitHub import): "Task hygiene" (universal=true) + "Working preferences" (universal=false). Fires for new projects only; existing projects unaffected.
2. MCP create_project (V2/supabase/functions/mcp/index.ts) — no longer inserts the baseline itself (trigger owns it; avoids double-seed). Its response now states the baseline was auto-applied and nudges the assistant to propose 2–4 project-specific IS additions for the user to confirm via create_is_entry (the "AI-proposed" half). Tool description updated.
