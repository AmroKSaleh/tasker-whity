PARKED build seed (Phase-2 B2B). The foundation + hardest/riskiest slice of the org/RBAC layer. Full design in KB "Org/RBAC layer — design + cost analysis (TDE-302)".

Scope: organizations + organization_members tables; environments.org_id (dual-owned: null=personal, set=org-shared); environment_grants (env-scoped access). THEN the security rewrite: a security-definer helper (can_access_environment/project) and rewrite ~20 tables' RLS from `auth.uid()=user_id` to grant-based; AND in-code grant enforcement across all MCP tools (MCP runs as service role → bypasses RLS, so this is mandatory, not optional).

Why a flow: multi-step with real handoff + a hard security gate (a wrong RLS/MCP check = cross-org data leak). Do NOT ship half-baked. Trigger to build = first paying multi-person team.

--- IN PROGRESS (2026-07-04): decisions settled + Step 1 (additive foundation) DONE ---
Being built incrementally in-session (safe-first), not via formal flow ceremony.

DECISIONS SETTLED (checklist resolved):
- Roles: 'admin' + 'member'; org creator = owner (organizations.owner_user_id). Admins create org envs + invite + grant; members see only granted envs. Members do NOT create envs.
- Access check: SQL SECURITY DEFINER can_access_environment(id) = personal (env.user_id=me) OR (env.org_id in my orgs AND (I'm org admin OR I hold an environment_grant)). Projects/tasks/etc inherit via environment→project.
- MCP enforcement: same check in code (assertAccess) in resolve* paths, since service role bypasses RLS.
- Perf: direct checks, no denormalized cache for v1. MCP acting-org: none — infer org from the resource (project_id→env→org).
