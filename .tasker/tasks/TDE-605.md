Idea (2026-07-18, parked for later discussion): a minimal read-only desktop viewer for Local Mode projects — parses .tasker/ folders on disk and renders project/task state. No auth, no Supabase, no sync logic; Local Mode already did the hard part (plain files).

Feasibility read from the initial discussion: technically easy (weekend-scale). Suggested stack: Tauri + small React view (V2 components are Supabase-coupled, so a fresh read-only view; tiny binary vs Electron).

Two design realities identified: (1) project discovery — .tasker/ folders live in arbitrary repo checkouts, so it needs either a registry file appended on pull_local_project or an "add folder" picker (registry preferred, cheap); (2) staleness — files only reflect last-pulled state, so the UI must show a "pulled X ago" stamp or it quietly lies.

Open strategic pushback (unresolved): the web app is already the inspector — a desktop viewer's only real edge is offline + zero-friction glance at what's on THIS machine's disk. If neither is the actual itch, it's a second inspector surface maintained forever for marginal value. Also arrived during board-cleanup mode (close/declutter, not new builds), so deliberately parked as a seed rather than actioned. Related positioning: "State Layer, Not Executor" / web-app-as-inspector decisions.
