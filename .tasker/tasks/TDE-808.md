THE HIGHEST-LEVERAGE UNFIXED THING ABOUT FLOWS. Every agent session is currently being steered by a definition we have already retired.

WHAT THE PLAYBOOK SAYS TODAY (the __init_tasker_session directives, served on every session): "use a flow only when ALL THREE hold — (1) multiple steps drive toward ONE goal, (2) steps HAND OFF to each other, (3) at least one handoff carries a real quality risk worth gating" and "A flow with no contracts is just ordered tasks — if nothing needs gating, it should not be a flow."

WHAT THE REVIEW SETTLED (see TDE-807 and its grounding artifact): SIZE is the requirement — a Flow is what a task becomes when the operation is too large for one stretch of attention to carry honestly. Connection between steps is OPTIONAL. Contracts/gates are OPTIONAL — a property of certain joins, not the definition. Kinds of Flow are distinguished by WHO EXECUTES (human / agent / both). The smallest real Flow is "more than two tasks can hold" — if it splits cleanly in two, it was never big enough.

So the current directive gets it backwards on three of four axes, and actively turns away the work that now qualifies (long sequential operations with no formal handoffs) while admitting work that no longer does (a tidy two-step draft-then-review). The TDE-807 artifact names this exact gap as the main practical risk: "the guidance an agent follows still describes the old centre, and will keep steering people by it until it is rewritten."

### ⚠ THE BRANCH IS NOT MERGED
Commit `6acff2a` on branch **`tde-808-flow-directive-rewrite`**. **The function was deployed FROM THAT BRANCH**, so the live directive and `main` currently disagree. Anyone deploying the MCP from `main` before this merges will silently revert the directive to the retired definition. Merge it.

### What changed (all in V2/supabase/functions/mcp/index.ts)
- **The FLOW vs AD-HOC directive in `ASSISTANT_DIRECTIVES`** — replaced wholesale. Leads with the canonical definition, then: two motives (either sufficient) · scale as the floor carrying the whole boundary · connection optional · contracts optional · runs-and-terminates vs container · the four granularity promotion triggers, pushing toward FEWER steps · no flow types · gate only at seams, dissolve before gating, order by blast radius · receiver-authored bar · the board-invisibility cost (TDE-320).
- **`build_new_flow`'s interview** — it would have contradicted the directive on the very next session. Changed: the `instruction` ("a flow = a chain of contract-linked tasks" → contracts optional, belong only at seams, do NOT interview for handoffs as prerequisites) · playbook step 3 (added the four promotion triggers, "aim for FEW steps", executor is per-step and never a kind of flow) · playbook step 4 (rewritten as FIND THE SEAMS THEN GATE ONLY THOSE — the would-the-next-step-notice test, dissolve-before-gating, blast radius, receiver-authored bar; the retired "only make a step its own task if it produces a contract-worthy handoff" granularity rule is gone) · playbook step 6 and the `set_task_input` persistence note (the gate applies only to DECLARED edges; an ungated flow finalizes cleanly and that is intended).
- **KB entry e5501d90** — retitled and rewritten. The TDE-255 PLACEMENT decision (guidance is a global directive, not per-project IS) survives; the guidance itself is marked replaced, with the reversals listed.

That axis was NOT encoded. Similarly, this task said not to encode a granularity rule because TDE-795 was open — it has since settled, so the four promotion triggers ARE encoded.

### FINDING — a gap the new model exposes, not fixed here
`contractGateViolations` (contract_gate.ts) iterates **declared input edges only**, so a flow with no edges finalizes cleanly and gateless flows needed no code change. BUT declaring an edge FORCES a non-trivial human-blessed contract on both sides — while the new model separates a **handoff** (no gate needed) from a **seam** (gate). There is currently no way to record "step 2 uses step 1's output" without gating it, so agents will simply stop declaring edges and the I/O graph loses information. The interview now says "do not wire edges you have no intention of gating", which is a wording patch over a modelling gap. Proper fix (an ungated edge) is a code change belonging to the rebuild decision on TDE-792.
