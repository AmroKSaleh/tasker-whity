WHY: The 3-phase interview rework (elicit → draft+probe → bless) was deployed as instructions inside bootstrap_project's return + global directive, and it DID NOT take — the FSV run still ran a 6-question multiple-choice quiz, no open elicitation, no brief-blessing, no scope pushback (user picked two mechanics, got zero challenge). Lesson: a big instruction blob in a tool return is too weak to beat the AskUserQuestion tile habit. Populate fixes (seeds/design/sections) landed because they're concrete actions; the interaction-style change did not. Cheap mitigations already shipped (fixed the stale directive that still described the old tile model; front-loaded a hard "don't open with AskUserQuestion" line) — expected to only partly work.

THE FIX — make bootstrap_project a gated, multi-call STATE MACHINE instead of one skimmable playbook:
- New `project_drafts` row: in-flight Foundation + status (eliciting → drafting → blessing → blessed).
- bootstrap_project(name, intent) → creates the draft, returns ONLY Phase 1 (open prose questions) + a draft_id. Does NOT reveal phases 2–3, so there's nothing to skip ahead to.
- bootstrap_advance(draft_id, ...) → walks phases one call at a time: submit user's free-text answers → get draft+probe step → submit drafted brief → get bless step → mark blessed. Advancing past Phase 1 REQUIRES submitting the user's free-text answers (indirectly forces real elicitation).
- finalize/create gated: project isn't created unless draft.status='blessed'.

ENFORCES: the sequence + blessed-brief-before-project (structural). CANNOT police literal "prose not tiles" (server can't see how the agent asked) — but one imperative gated phase at a time is far stronger leverage than a blob.

OPEN DECISIONS (resolve before building):
1. Where does blessing happen — in CC (agent shows brief as text, user blesses in chat; simplest, ship first) OR in the web app (render draft brief + Edit/Bless button; richer, more build)? Lean: CC first, app view later.
2. How hard to gate — lock only the bootstrap PATH (finalize requires blessed) and keep plain create_project as a deliberate quick/empty escape hatch, OR also make create_project itself refuse/warn when an unblessed draft is in flight? Lean: enforce bootstrap path, keep create_project as a clearly-secondary escape hatch.
