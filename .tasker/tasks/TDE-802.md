## OUTPUT — when NOT to use a Flow (settled 2026-07-28)

### First, this task's own stated "current answer" is DEAD
*"A flow with no contracts is just ordered tasks"* was rejected by Q2 (scale is the essence, contracts optional) and explicitly re-confirmed by the user here: **a gateless flow IS a flow.** The anti-pattern list is rebuilt without it.

### THE TWO MOTIVES (user's formulation — the clearest statement of the definition so far)
There are exactly two reasons to reach for a flow:
- **RUN IT RIGHT** — the operation is sensitive, so seams get gated and quality is protected at the joints.
- **HOLD IT TOGETHER** — the operation is big, so it gets durable structure, resumability, legible progress, and protection from drift and the context wall.

These map exactly onto Q1's eight symptoms, sorted: self-approval and handoff-quality rot belong to the first; drift, context wall, resumability and legibility belong to the second. Q1 found the symptoms and never sorted them; this sorts them into what a flow is FOR.

**Guard: these are NOT types.** Q6's razor (does it vary inside a single flow?) kills that immediately — a big sensitive operation carries both motives at once, gated at one seam and purely structural everywhere else. They are reasons to reach for a flow, never a property stamped on one.

**Cleanest test this yields: which motive applies? NEITHER → it is not a flow, it is tasks.** Either or both → it is, and the motive tells you what to build (gates for the first, structure for the second).

### CONTAINER vs OPERATION — the line that stops flows swallowing projects
"Structure for big work" describes a project just as well as a flow. The separator is **termination by execution**:
- **Container** = a place things live in indefinitely (project, section, group, phase). It holds; it does not run. A phase ends when you DECLARE its condition met, not by executing to completion.
- **Operation** = something you do. It starts, runs, finishes, produces a result. There is a last step.

Test: can you keep adding unrelated work to it forever without that being strange? → container. Does it have a final step after which it is finished? → operation.
**Anything that never terminates is not a flow, however big it is.**
Practical tell: *if you find yourself wanting to add unrelated work to a flow later, you built a container and mislabelled it.*

Note on wording: the user's "contained" means *held together so it doesn't sprawl* (one big thing, bounded) — that is the HOLD IT TOGETHER motive and is still an operation. Distinct from "container" = a place for many unrelated things. Keep the two senses apart or the project/flow line collapses.

### THE ANTI-PATTERN LIST
- **Fits fairly in ~2 tasks** — Q2's scale floor. With gates optional, this floor now carries the ENTIRE boundary against plain tasks, so it must be crisp enough to enforce during flow-building: *"can't be fairly held in about two tasks without a wall of context."*
- **Never terminates** — a container. Use a section, phase or project.
- **You need it visible on the board** — flows are hidden from the board (TDE-320). That is a real, under-named cost. Concrete test: **would you accept this work vanishing from the board?** If visibility matters more than structure, don't.
- **Manufactured gates** — reaching for a flow because contracts feel rigorous, on work with no genuine handoff risk. Pure overhead.
- **Needs ~40 micro-steps** — Q3's legibility cap. A flow's own legibility bounds its step count; cut coarser, or admit it is a project.
- **Neither motive applies** — the summary test.

### EXPLICITLY NOT anti-patterns (all previously believed to be)
- **No contracts anywhere.** Minimum viable flow = ordered steps + durable state + resumability + legible progress. The current directive discourages this and the build interview pushes toward contracts — **both must stop (TDE-808).**
- **An all-human executor** (Guide Mode) — Q6.
- **A flow that discovers its own steps as it runs** — Q6.
- **Homogeneous batch work** (clean 300 tasks, migrate 80 files) — Q3.

### Gap to fill later
No anti-pattern was contributed from REAL use — the list is reasoned, not observed. Worth revisiting after the next few dogfooded flows: something that was made a flow and shouldn't have been is worth more than anything derived here.
