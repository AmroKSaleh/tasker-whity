Ampersands are stored HTML-escaped in the database, so users see the literal text "&amp;amp;" instead of "&amp;".

This is a DATA bug, not a rendering bug — the corruption is in the stored value, confirmed three independent ways:
1. The web app displays "design &amp;amp; open questions" on the board (screenshot: Z:\Tasker\_check\shots\desktop.board.png, Next Up panel).
2. The MCP get_task on TDE-261 returns the title as "Task-level independent review (judge) — design &amp;amp; open questions" — so it is not the frontend escaping at render time.
3. That task's generated git branch is "tde-261-task-level-independent-review-judge-design-amp-ope" — the slugifier saw "amp" as a word, proving the entity was already in the value when the branch name was derived.

Not limited to tasks. At least two KB entry titles are affected:
- "Judge: TDE-261 Phase 1 shipped — architecture &amp;amp; the review≠flow-ledger gotcha"
- "Case: Brand DNA Drift in Image Prompts — context placement &amp;amp; conformance (2026-06-14)"

So some write path (or a historical migration/import) HTML-escaped input before persisting. Needs the write path found and fixed first, then a cleanup pass over existing rows — fixing only the data will let it re-corrupt.

Found 2026-08-02 during a full web-app sweep.
