Resolved from seed 2026-07-18. Add rename/delete/reorder of groups AND sections through .tasker/ files — the half create-by-reference can't do (rename moves a name-derived slug → orphans task refs). The 5 seed questions are SETTLED (user took the recommended package):

Q1 FORMAT → a DEDICATED writable manifest file in .tasker/ (e.g. structure.json), NOT making project.json writable. project.json stays a pure read-only regenerated snapshot; the manifest is the one file (besides tasks/*.md) that flush APPLIES. It lists sections + groups: each line = { slug (stable id), name (editable), order, and for groups: section (parent slug) }.

Q2 IDENTITY → FREEZE THE SLUG. A group/section gets its slug ONCE at creation; it NEVER changes when the name changes. Tasks reference the frozen slug. THIS REQUIRES A SCHEMA MIGRATION: sections and groups currently have NO slug column (verified — slug is computed on every pull via buildSlugMap in sync_core.ts). Add a `slug` column to both tables, backfill from the current computed slug, and rewire buildProjectMeta/buildPullMaps to READ the stored slug instead of recomputing. This is the biggest/riskiest part — it touches the identity layer the whole file format hangs on.

Q3 DELETE → group delete (line removed from manifest) = its tasks fall to UNGROUPED. Section delete = REFUSE if the section still has tasks/groups (must be emptied first); only an empty section deletes via files.

Q4 CONFLICT → whole-manifest last-write-wins by the manifest's own timestamp (same model as task LWW). Structural ops are rare + single-user-across-devices; no per-line merge.

Q5 SECTION DELETE → via files but ONLY when empty (per Q3). Section rename + reorder via files are unconditionally fine.

BUILD ORDER: (1) migration — add slug col to sections+groups, backfill, atomicity; (2) rewire slug maps to read stored slugs (buildPullMaps/buildProjectMeta in sync_core.ts) — verify create-by-reference (TDE-581/section) still works after the switch from computed to stored slugs; (3) emit the manifest file in buildLocalBundle; (4) make flush APPLY the manifest (rename/delete/reorder for groups+sections, with the Q3/Q5 delete guards); (5) manifest LWW; (6) node tests + LIVE verify with a THROWAWAY task/section per the testing rule; (7) update .sync.json hashing (generic loop already covers new files) + README + flush_local_project tool docs.

Backfill must produce the SAME slugs tasks already reference (dedup order matters — buildSlugMap appends -2/-3 in list order; preserve it). project.json currently regenerates slugs too (serializeProjectJson via buildProjectMeta) — must switch to stored.
