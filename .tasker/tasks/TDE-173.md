Make new/changed tasks & events appear in the web app live (e.g. a task created via MCP shows up without refreshing). Currently the cloud app uses Zustand + manual fetches, so MCP/other-device changes only appear on refresh.

Feasibility (assessed 2026-06-02): LOW-TO-MODERATE, ~a day — the platform already supports it.
- Use SUPABASE REALTIME: subscribe to postgres_changes on tasks/sections/projects (filtered by user/project), and on insert/update/delete call the EXISTING Zustand store actions (addTask/updateTask/removeTask). Mostly: enable Realtime/replication on those tables, add one subscription hook, map events → store mutations.
- Gotchas: enable Realtime on the tables; RLS applies to the subscription (respects per-user access); handle reconnection on network blips.
- NOTE: the local lens (@tasker/local) ALREADY does this via SSE (server.js broadcasts on file change). So this is bringing the CLOUD app to parity with the local lens, using Supabase Realtime instead of SSE.
- High-leverage: fixes a daily friction and benefits BOTH audiences (dev-via-MCP and web-app user). Related: [[Persistency across platforms and devices]] (TDE-170).
