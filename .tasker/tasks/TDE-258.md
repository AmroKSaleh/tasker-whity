Add a tool (e.g. get_kb_entry(entry_id)) that returns the full content of a SINGLE KB entry.

Context / why (discovered 2026-06-14 while scoping an image-generation style guide in WCP):
- Today the MCP has list_kb_entries (returns id + title + source + updated_at ONLY — no content) and get_knowledge_base (returns ALL entries WITH full content). There is no way to read one specific entry's body.
- Consequence: when a task wants to "reference the X KB entry," the agent can see titles cheaply but must pull the ENTIRE knowledge base to read that one entry's content. Token cost and context noise scale with the whole KB.
- This makes KB-reference workflows progressively worse as the KB grows, and pushes users toward embedding instructions directly into tasks instead (the workaround we chose for the Waqtak Visual Identity guide).
- A get_kb_entry(entry_id) tool would let a task pull exactly the one entry it needs, making scoped reference cheap and viable. Pairs well with the proposed task/section-scoped auto-injected instructions idea.
