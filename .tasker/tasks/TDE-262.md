Make new projects start with the right knowledge baked in, two complementary parts:
1) Let the user define their OWN default Instruction Sets and KB entries that auto-seed every new project (beyond the built-in baseline IS) — reusable personal/org defaults.
2) At project creation, interview the user about which ISs and KBs the project should carry, so the project starts grounded instead of empty.

Ties into the broader context-placement work (project/section/task-scoped IS, the judge's contract being assembled from KB+IS). Good defaults + a creation interview = the truth source that later lets task creation avoid grilling the user every time (see the task-level judge task, milestone on task-creation thoroughness).
