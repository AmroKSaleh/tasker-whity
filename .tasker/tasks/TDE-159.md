title: How about Flows having their persistent KBs and ISs?
status: pending

Product idea: let a "Flow" (a defined multi-step process within a project) carry its own persistent Knowledge Base and Instruction Set entries, scoped to that flow rather than the whole project. So when an agent executes any step/task belonging to a flow, the flow-specific KB (reference/rationale) and IS (binding rules) are automatically in context, independent of whatever the agent already knows.

Origin: surfaced 2026-05-31 while building an "article release flow" in the WQW project. We had to attach the flow's context via a project-level KB + IS and replicate context into each step task manually, because there is no flow-scoped persistent context layer. A flow-level KB/IS would make a flow self-contained and portable across agents/sessions.
