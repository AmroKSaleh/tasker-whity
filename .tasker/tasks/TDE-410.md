Flow step (Local Mode v1 Build — design: V2/docs/local-first-design.md D3/D4/D7/D8). Two new MCP tools in V2/supabase/functions/mcp/index.ts using local_format.ts:

pull_local_project(project_id, device_id, cursor?) → refuses non-local_mode projects; returns ready-to-write file map: project.json, tasks/*.md (all when cursor absent, changed-since-cursor otherwise), context.md (Foundation+IS+KB-index snapshot, read-only), README.md (agent workflow instructions), .gitignore entries (.sync.json, context.md), .sync.json content (new cursor, per-file hashes, leased ID block start/end), plus tombstoned short_ids since cursor. The AGENT materializes files to disk (the hosted fn cannot touch the device).

flush_local_project(project_id, device_id, base_cursor, changed_files:[{path,content}], deleted_short_ids?) → parses via serializer; per-task LWW by frontmatter updated_at vs DB updated_at (conflict only when DB local_rev > base_cursor); edit-beats-delete on tombstone races; new tasks accepted only within the device's leased ID block; writes tombstones for deletions; bumps local_rev; returns new cursor + list of tasks where the hub won (agent rewrites those files locally).

Owner-only is inherent (user_id-scoped MCP). Definition of done: scripted two-device simulation over the sync core passes — concurrent edits resolve to newest updated_at, tombstone propagates, concurrent edit beats delete — script exits 0. Deploy with --no-verify-jwt.
