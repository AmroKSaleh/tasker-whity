Currently update_task's `detail` param REPLACES the entire detail field. To make a small addition you must resend the whole detail — costly in tokens, error-prone, and risks silently dropping existing content (hit this exact friction on 2026-06-04 reframing TDE-137: had to resend the full detail twice).

Add an APPEND capability — e.g. an `append: true` flag (append the provided text to existing detail) or a separate `append_detail` param — so callers can add context/notes without resending everything. Keep replace as the default for backward compat.

Why it matters:
- Token economy for the dev/MCP audience (they pay per token; full re-sends are wasteful).
- Directly serves the "tasks as durable memory" goal (TDE-170, [[Persistency across platforms and devices]]): accumulating context onto a task over time IS the core workflow, and append is the natural primitive for it.

Implementation: in the update_task handler (V2/supabase/functions/mcp/index.ts), if append flag/param is set, fetch existing detail and concatenate (with a newline) instead of overwriting.
