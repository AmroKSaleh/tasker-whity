BLOCKS "Run round 2...". Goal: build a harder objective task so the independent validator finally gets a fair test.

WHY: Round 1 used a small pure function (parse_duration). Arm C (spec-only) hit 100% — a clear spec alone was sufficient, leaving the validator NOTHING to catch (ceiling effect). So round 1 could only prove the contract's value (+28.9pp A->C), not validation's. Round 2 needs a task where even WITH a complete spec, a strong model (Sonnet) still slips — i.e., spec-only (Arm C) should land roughly 60–80%, not 100%. Only then can we measure whether the validator (Arm B) recovers the gap (B > C).

WHAT MAKES A GOOD ROUND-2 TASK: keep round 1's virtues — objective ground truth (hidden pytest oracle, no judge needed), bespoke (defeat memorization), cheap to run (pure-ish Python, no infra). Add difficulty via MORE interacting edge cases / ambiguity / state. Candidate shapes: a mini expression evaluator/tokenizer with operator precedence; a stateful recurrence-rule parser; a spec-driven data transformer with cross-field validation; an algorithm with many interacting constraints. Pick one where a complete spec is necessary but not sufficient.

DIFFICULTY CALIBRATION LOOP: draft the task + oracle + contract; pilot Arm C 2–3 times (subagent, Sonnet); if C ≈ 100% make it harder, if C < ~40% make it easier; target C ≈ 60–80%.

DELIVERABLES (mirror round 1's harness): a round2/ subfolder under V2/experiments/contract-gating/ containing test_*.py (hidden oracle), contract.md (full spec for arms C/B), loose_prompt.txt (arm A), solution_reference.py (verify the oracle is 100% vs reference FIRST). Then append the round-2 task + oracle summary + hypothesis to the pre-reg doc (V2/docs/experiments/contract-gating-preregistration.md) and COMMIT it before running (same pre-registration discipline as round 1 — the commit is the lock).
