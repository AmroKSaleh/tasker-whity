From the board UX review (see TDE-346 for full framework + the approved A/B mockup: https://claude.ai/code/artifact/221f1d5d-b93c-491e-ab74-758e5c594fc0). Build the highest-priority state in the app: an AI task that hit a contract/quality gate and needs a human.

Design (LOCKED):
- Signal color = INDIGO #4B57D8 (NOT red — red is quarantined for systemic outages; a gate failure is a handoff, not a crash). Cool temperature break makes it pre-attentive against the warm/orange board.
- FULL state: solid indigo left bar + faint indigo tint + a "NEEDS REVIEW" state-chip + the failing reason in one line (e.g. "Contract failed — 620 words < 1,000 min") + a primary "Review →" action on the card.
- MULTIPLE failures in one column = topology-ranked progressive disclosure: only the earliest upstream choke point renders FULL; downstream blocked tasks go SLIMLINE (indigo bar + icon + title only); tail collapses to "+N more blocked".
- Surfaces in a right-rail "Needs you" zone; its count should drive the left-rail notification badge.

PREREQUISITE / open question: does the data model even expose this state yet? Need a way to know a task is blocked on a failed contract gate (validation/review status). Check tasks.review_* columns and the flow validation results (submit_validation_result / get_validation_feedback / get_task_critique). This likely needs MCP/schema support before the frontend can render it — scope that first. Also resolve the mockup's open items: dark-theme indigo variant, colorblind check, real glyph (◆ was placeholder).

--- SCOPE LOCKED (discussed 2026-07-01): SCOPE A only ---
Surface the FAILURE-ESCALATION state that already exists — do NOT build a happy-path "human sign-off before done" (that's Scope B = TDE-261's deferred "human override / async-for-human completion" milestone; decide separately).

Corrected understanding from the discussion:
- The "independent task needs human" state is TDE-261's task-level judge: enable_task_review freezes a bar → judge grades output → blocker fail reopens to in_progress for AI SELF-REVISION (attempts 1-2, NOT a human state) → on the 3rd failed attempt it escalates: action=ask_human and tasks.review_verdict.escalated = true.
- THE LOUD CARD MUST KEY OFF review_verdict.escalated === true ONLY (the terminal "AI gave up" state). A single/second failure is the AI retrying = in_progress = NOT your problem yet. Rendering every fail would be pure noise. (My original mockup keyed off "gate failed" — wrong.)
- NOT blocked on backend: review_verdict already persists on the task row; the board already selects '*' so review_* flows to the client; ReviewVerdictPanel + a list-item badge already exist. So this is largely a FRONTEND surfacing job — bring the escalated state up to BOARD level with the pre-attentive indigo treatment (TDE-346 framework + mockup https://claude.ai/code/artifact/221f1d5d-b93c-491e-ab74-758e5c594fc0), plus the "Needs you" right-rail zone driving the left-rail badge.
- This is effectively the UI for TDE-261's deferred "async-for-human completion" milestone — LINK to TDE-261.
- Flow tasks have a SEPARATE escalation (validation loop → ask_human, retry_blocked). Review is mutually exclusive with flow tasks. Unifying both sources into one "Needs you" surface is a nice-to-have; the independent-judge case (review_verdict.escalated) is the primary build.
