Mined from Plane's saved custom Views / filters.

WHY CAUTION: saved views are human-PM convenience adjacent to the coordination lane. On its own it's feature-creep. BUT it maps cleanly onto something we already want.

THE MOVE: do NOT build a standalone "Views" feature. Build the WIQL-style query surface already logged as TDE-556 ([STEAL] query surface over the I/O + flow graph), and let human "saved views" be a thin wrapper that persists a query + renders it in the web inspector. ONE query engine, TWO faces: agents query it programmatically (MCP), humans save/name queries as views (web app = the human-inspector surface, on-wedge). This keeps it on-brand and avoids a second, redundant filtering system.

DEPENDS ON: TDE-556 (the query surface). This task is essentially "the human-facing half of TDE-556" — consider folding it into TDE-556's scope rather than building separately. NEXT STEP: when scoping TDE-556, include a persist-and-name-a-query affordance for the web app; if done there, close this as covered.
