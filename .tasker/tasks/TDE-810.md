WHY: both documents read as current maps of Tasker and are not. A new session (human or agent) that opens either one is grounded on a product that no longer exists — and both are the most inviting files in the repo to open first.

V2/ARCHITECTURE_BRIEF.md — describes v0.3.2: no flows, no contracts, no environments, no orgs, no connectors, no Local Mode, no agent layer. Also documents in-app AI as central, which the b65fb8c5 KB decision has since re-affirmed for different reasons, so the doc is misleading in both directions. Its closing section is a request for architecture proposals that was answered long ago.

V2/AI_PRIMER.md — lists an MCP surface of roughly 25 tools. The live surface is ~200. It also carries {placeholder} template variables that were never filled. The current reference is docs/mcp-tools-reference.md.

ALSO IN SCOPE: the root app/ folder is the pre-V2 app. All active development is in V2/ (verified via git log — every recent commit touches V2/). Leaving a second, stale React app at the repo root will confuse contributors the moment the repo is public, so decide now: archive it, delete it, or clearly label it. This matters for the open-source launch, not just for us.

FIX APPROACH: do not delete the documents — add a dated header at the top of each ("HISTORICAL — describes v0.3.2, superseded by X, retained for context") and point to the live reference. Cheap, preserves history, stops the misgrounding.
