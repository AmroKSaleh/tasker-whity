KEYSTONE for all Google service connections below (Drive, Gmail, Tasks). Build the reusable OAuth + token layer ONCE; each service then just adds its scope + API calls. Do this first.

Scope:
- Per-service "Connect <Google service>" button that triggers a Google OAuth flow requesting that service's scope, independent of the login OAuth. Users re-consent per service — that's fine.
- Token storage: store access_token + refresh_token per service in user_settings (mirror the existing GitHub/Google token-storage pattern).
- Refresh helper in the MCP that calls Google's token endpoint when an access token is expired and persists the new one. THIS is the bulk of the work and the piece every service reuses.

Context: the app already has Google OAuth for login, and Google Calendar (events) is already integrated. This generalizes that into a reusable per-service connect + refresh mechanism.

Architecture chosen: auth-code flow, ONE shared Google connection per user; scopes accumulate via incremental consent.

Files:
- migrations/20260613140000_add_google_oauth_tokens.sql — adds google_access_token / google_refresh_token / google_token_expiry / google_scopes on user_settings.
- functions/google-connect/index.ts (deploy WITH jwt) — authed; returns a Google consent URL with HMAC-signed state (access_type=offline, prompt=consent, include_granted_scopes=true).
- functions/google-callback/index.ts (deploy WITH --no-verify-jwt) — verifies state→userId, exchanges code for access+refresh, upserts tokens (never nulls an existing refresh token), merges scopes, redirects {APP_URL}/settings?google=connected|denied|expired|error.
- mcp/index.ts — refreshGoogleToken() + loadGoogleAccessToken(sb,userId): reusable server accessor returning a valid token (auto-refresh on expiry, 60s skew). Drive/Gmail/Tasks tools call THIS. (deno-lint-ignore no-unused-vars until first consumer.)
- app/src/lib/google.js — connectGoogle(scopes), loadGoogleConnection, hasGoogleScope, disconnectGoogle + GOOGLE_SCOPES {drive, gmail, tasks}.
