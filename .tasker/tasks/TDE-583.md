GAP found 2026-07-17 while demoing the TDE-348 escalation card. There is currently NO MCP tool (and, to confirm, likely no web control) to turn OFF task-level review once enabled, or to clear/reset a review_verdict — including a stuck review_verdict.escalated=true. enable_task_review only turns review ON and freezes a bar; clear_task_output clears OUTPUT CONTRACTS, not review verdicts; the only way to clear an escalated card today is to submit_task_review with a passing result, which is dishonest metadata (it records a "pass" on output that was never really produced/accepted).

WHY IT MATTERS:
- No escape hatch: a task with review enabled by mistake, or escalated by a bad/obsolete bar, is stuck wearing the indigo NEEDS REVIEW card with no clean way back to a normal state.
- Faking a pass corrupts the review ledger — exactly the durable, trustworthy quality-gate record that is the moat. The one clean-up path currently available undermines the thing review exists to protect.

DESIGN QUESTIONS (settle before build):
- New tool disable_task_review(task_id): turn review OFF and clear the frozen bar + verdict, returning the task to un-reviewed. Should it require force if a verdict exists?
- Separate clear_review_verdict(task_id) that keeps review enabled but resets the verdict/attempt counter (e.g. to re-review after fixing the bar)? Or fold both into one tool with a mode.
- Immutability tension: review activity/verdict history may be intended as append-only provenance (cf. TDE-374 agent-session ledger immutability). If so, "clearing" should be a NEW superseding event (verdict=cleared, with reason), NOT a destructive wipe — preserve the trail, change the derived state. Decide the model.
- Web affordance: a control on ReviewVerdictPanel to disable review / dismiss an escalation, with confirm.
- Guard: who can clear — owner only.

POINTERS: review machinery = TDE-261 (task-level judge); tools enable_task_review / review_task / submit_task_review / get_task_critique; escalated card = TDE-348 (done) + TDE-562 (remaining slices). Immutability precedent = TDE-374.

NEXT STEP: decide destructive-clear vs superseding-event model, then add the tool + web control.
