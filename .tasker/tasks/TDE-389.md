From Linear: the MCP endpoint accepts bearer tokens directly alongside interactive OAuth — including RESTRICTED API keys, so "read-only key = read-only MCP session" with scope enforced in the token, not per-tool config; admins revoke/change agent permissions anytime (PermissionChange webhooks); agents are constrained to the teams selected at install. Enterprise puts MCP auth behind SSO.

Build: token-level scoping for Tasker's MCP — (a) read-only keys: a session authenticated with one gets reads only, writes refused server-side; (b) agent tokens respect environment/org grants — THE pending "MCP in-code enforcement" piece of the org layer (TDE-359/360): a token granted only Env X cannot touch projects outside it; (c) immediate revocation from the admin UI.

Later polish, same task family: OAuth 2.1 + dynamic client registration on the MCP endpoint (Linear's pattern) once third-party/teammate agents connect — not needed while it's one user's bearer token. This is what makes org/RBAC real for agents, not just for the web app.
