The RECEIVER half of the autonomy loop. TDE-377 (outbound webhooks) is the emitter — Tasker fires a signed event when a task is confirmed / a flow unblocks / a review lands. This task builds the thing that CATCHES that event and turns it into real work with the user's PC closed.

WHY: The prepare→confirm→execute loop already works, but today it needs the user's IDE open (pull via get_ready_work). The user's key call this sprint: confirm-in-IDE is ceremony unless the agent runs INDEPENDENTLY of their PC. This task delivers that.

ARCHITECTURE (agreed): trigger-spawns-session, NOT poll-an-open-session. On webhook receipt, launch a fresh headless `claude -p "work the ready queue"` run against the repo; it calls get_ready_work → works the top confirmed task → writes to the agent ledger (TDE-374) → completes. Idle cost = $0 (no polling); you pay only when there's real work. Empty-poll math that killed the polling option: a 30s loop idles at ~$600/mo to hear "nothing ready." Per-task cost of real work ≈ $1–5 on Sonnet (tokens dominate; compute negligible).

DEPENDS ON: TDE-377 shipping first (needs the signed emitter + payload/HMAC scheme to reuse). This dependency is intentionally NOT a flow I/O edge — kept as plain ordered tasks per the no-flows decision; the ordering is documented here, not hard-enforced.

OPEN DECISION that gates the build: WHERE the always-on receiver lives. Options — (a) Supabase edge function as the listener that shells out / calls a runner API; (b) a tiny always-on VM running the loop; (c) Anthropic Managed Agents scheduled/triggered deployment (Anthropic hosts loop + per-session sandbox + github_repository resource — least infra to own). Settle this first.

Cold-reader pointers: cost analysis + the polling-vs-trigger reasoning are in the Agent-Native Layer build report (this sprint). Managed Agents surface is documented in the claude-api skill. Agent identity/provenance for the runner's writes = TDE-375 (agent_label). Stop signal to honor = TDE-384 (stop_flow). Scoped read/write creds for the runner = TDE-389 (deferred).

PARKED 2026-07-13 — not being built now. Decision: the user's priority is ZERO marginal cost, and PC-closed cloud autonomy inherently costs API $ (runs outside the flat-rate Claude Code subscription). The fundamental tradeoff: zero-cost ⇒ subscription ⇒ runs on the user's machine; PC-closed ⇒ cloud ⇒ per-token API cost. User chose zero-cost. So we built Path A instead: an unattended polling loop inside Claude Code on the subscription (`/loop <interval> /work-loop`) — $0 marginal, but requires an open session + PC on. This receiver (Path C) stays parked as the future option IF the user ever wants PC-closed autonomy and accepts API cost. All the design + host analysis above still stands for that day.
