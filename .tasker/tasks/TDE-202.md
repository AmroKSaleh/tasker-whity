WEAKNESS: `submit_validation_result` accepts `{rule_id, status, note}` — a bare claim. The agent can pass anything with a polite note (exactly what happened in the test run).

FIX: require EVIDENCE per rule — the command output, the matched/failing lines, a screenshot path, the rendered diff — so a human or auditor can see WHY a rule passed/failed, not just that the agent said so. Raises the cost of a hollow pass and feeds the audit trail (#validation-audit-trail).
