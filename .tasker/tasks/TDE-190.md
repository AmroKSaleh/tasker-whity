## The question
When the AI builds a brand-new flow via interrogation (creation mode — see TDE-189), should it decompose the goal FORWARD (start → … → goal) or BACKWARD (goal → … → start)?

## Current decision
DEFAULT = FORWARD, chosen because it feels more natural to the user (who is a member of the target audience — a legitimate tiebreaker). To be validated empirically here, not assumed.

## What the test must check
- **Forward's weak point:** it needs a known STARTING POINT, but the hard case is "the user doesn't even know their current state." So forward mode needs a light opening grounding move ("what do you already have / where are you now") — codebase-first can supply this for the dev/MCP audience. Test whether that grounding step feels natural or clunky.
- **Backward's lost virtue:** backward discovered the current state for free (chain bottoms out at what the user already has). Test whether forward's explicit grounding step is a worse or acceptable substitute.
- Which direction produces a better-shaped flow (right number of tasks, right grain) with a real goal?
- Which one users actually follow without getting lost?

## How to test
Run both directions on 2-3 real goals (e.g. "write + publish an article", a small dev feature) via the agent + AskUserQuestion, compare the resulting flows and the felt experience.
