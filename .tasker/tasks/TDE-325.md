Add a built-in scheduling layer so tasks/flows can trigger on TIME, not only on dependency completion. Two modes:
- Looping / recurring: fire on a cadence (daily, weekly, cron-style) — e.g. a weekly newsletter task.
- Non-looping / one-time: fire a task or flow at a set future time.

WHY (motivation): the WCC content calendar currently lives OUTSIDE Tasker specifically because Tasker has no scheduling layer (see project content-calendar notes). A scheduler would bring that kind of time-driven work into Tasker.

Design questions to settle when building (merged from the former TDE-301 feasibility-discussion task, deleted 2026-06-30):
- Trigger types: time/cron, interval, one-shot.
- What gets fired: a task status change, a flow run, or a reminder/notification.
- Execution model: how it interacts with agent-run vs user-run execution — ties to the guide-mode / executor attribute work (see Flows section + KB "Guide Mode — executor attribute", TDE-281).
- Persistence + missed runs: what happens if the app/agent isn't active when a scheduled time passes (catch-up? skip? queue?).

Note: this task's title emphasizes recurring, but the scheduling layer should account for the one-time/non-looping mode too (the two share the same trigger/persistence machinery).

Design input from the Linear deep-dive (2026-07-10, see Linear Stuff section / KB "Linear deep-dive → Linear Stuff build map"): Linear's recurrence model is worth copying — the next occurrence is created only once the previous one's due date passes (00:01 the following day, user's timezone), not on a blind cron; any existing issue can be converted to recurring ("Convert into → Recurring issue"); edits to the recurrence template do NOT retroactively propagate to occurrences already spawned; a "Recurring issues" filter + a settings list manage them. Tasker additions: recurring occurrences should auto-surface on Today when spawned, and recurring FLOWS (our differentiator — Linear only recurs issues) follow the same spawn-on-completion-of-cycle logic.
