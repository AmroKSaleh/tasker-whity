Export a whole Tasker project to a portable file and import it back — into the same or a different account. Chosen as the grounded alternative to the parked multi-login work (TDE-304): moving a project between the user's OWN accounts becomes export → import, with ZERO RLS/auth surgery. (It gives a copy, not a live shared view — that's the accepted tradeoff.)

PRIOR ART CHECKED — not reusable: github_import_project only pulls open GitHub issues into tasks; github_push_project only syncs issue title/body/state. Both lossy (no flows, contracts, KB, IS, foundation, groups, milestones). This is a new capability.

FIDELITY (what the bundle must carry): the value of a Tasker project is NOT the task list — it's the flows/contracts/KB/IS/Foundation. Export full graph:
- project: foundation, context, instruction set, prefix
- sections, groups
- tasks: text, detail, priority, status, due, sorting_order, pinned + milestones
- I/O edges, output contracts, flow identities + flow context + steps
- KB entries, IS (instruction set) entries
(Decide at build time whether drafts/intake_jobs/artifacts are in scope — lean: skip ephemeral intake state.)

THE HARD PART — reference remapping on import: I/O edges, flow steps, and contracts reference task UUIDs. Import must mint FRESH ids for every row and remap all internal references (no UUID reuse — they'd collide / belong to another account). Reassign a fresh short-ID prefix to avoid collisions with existing projects. This is where the care goes; everything else is straightforward serialize/insert.

DESIGN DECISIONS (recommended, confirm):
- Clone-on-import semantics: fresh ids; a flag for whether task STATUSES carry over (backup → keep; template/share → reset to pending).
- MCP-first: export_project → JSON, import_project ← JSON (AI is the first-class user). Web Download/Upload .json surface layered on top for humans.
- Bundle = versioned JSON (schema_version field) so future format changes stay importable.

OPEN LEVER (user's call): full-fidelity in v1 vs leaner first cut (task tree + foundation now, flows/contracts/KB later). Lean = full-fidelity; a half-export that drops flows is the thing you'd regret when moving a project between accounts.

Deploy per project rules: MCP → Supabase Edge Functions (--no-verify-jwt), frontend → Netlify.

--- BUILT 2026-06-23 (MCP tools, deployed; live verification pending) ---
Implemented in V2/supabase/functions/mcp/index.ts. NO DB migration needed — export = read rows, import = insert rows with fresh IDs (pure edge-function logic).
- export_project(project_id) → full-fidelity JSON bundle (version 1): project.context/Foundation, sections, groups, tasks (verbatim via select '*' so column drift carries free), flows, project_statuses, task_statuses, flow_instructions, flow_knowledge, project_knowledge, project_instructions, task_discussions (milestones).
- import_project(bundle, name?, reset_progress?) → always a NEW project (fresh slug/prefix). Pre-mints new UUIDs for sections/groups/flows/statuses/tasks; remaps section/group/flow/custom_status FKs + tasks.input.edges[].source_task_id + spawned_from_seed_id (2nd pass) + legacy output.target_task_id. Clears the auto-seeded baseline IS before inserting the bundle's IS (avoids dup). reset_progress=true → all tasks pending (template); default preserves status/completion (backup).
KEY DECISIONS: (1) PRESERVE task short_id on import — new project is empty so originals stay unique AND it sidesteps the per-project MAX+1 trigger's batch-collision risk (trigger only fires when short_id null). (2) REGENERATE flow short_id — it's unique per ACCOUNT (partial unique index flows_user_short_id_idx), can't be preserved.
Typechecks clean (no new deno errors; pre-existing implicit-any noise untouched). Deployed --no-verify-jwt.
