From Linear: the editor @-mentions issues, projects, documents, and dates; referencing an issue ID in any description/comment AUTO-CREATES a "Related" relation; documents and issues form a traversable reference graph with backlinks.

Build: mentioning TDE-X (or a KB entry) in a task detail, note, or KB body auto-creates a typed reference; backlinks render on both ends (task shows "referenced by…", KB entry shows which tasks cite it); an MCP affordance to traverse references (cousin of get_task_connections, but for context links).

Hard boundary, stated up front: these are ADVISORY context links only — no blocking, no gating, no dependency semantics. Flows remain the only dependency mechanism, and they stay off the board (locked decisions). This is about agents traversing context graph-wise instead of keyword-hunting: "the task that cites the decision that cites the report."

Cross-ref: TDE-313 (task cards list attached/connected items — the display sibling), memory-file [[name]] linking as the pattern precedent.
