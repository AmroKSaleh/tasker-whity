BIGGEST gap between the lens story and the code. Current GitHub MCP tools are IMPORT-ONLY / one-way (GitHub → Tasker/Supabase):
- github_import_project: fetches open issues → creates Supabase project, labels→sections, issues→tasks (caps at 500).
- github_sync_issues: pulls only NEW open issues, additive.
- github_connect / github_disconnect / github_list_repos.

There is NO write-back to GitHub anywhere. The "edit in Tasker → push to update GitHub" loop the founder describes is NOT implemented — today even the "lens" is really "import + store in Supabase." The repo-file path (.tasker via GitHub Contents API) is marked "future."

To make lens mode real (currently ~40/100): build write-back so Tasker/local edits flow back to GitHub issues (and/or the repo's .tasker files). This turns import-and-store into a true bidirectional lens.

Files: V2/supabase/functions/mcp/index.ts (github_* handlers ~line 1331+), V2/app/src/lib/github.js.
