Feasibility (assessed 2026-06-02): a spectrum, and per-app bespoke.
- Outbound notifications (Tasker → Slack): EASY (~half a day). Store a Slack incoming-webhook URL / bot token (reuse the user_settings token-storage pattern used for GitHub/Google) and POST on task events from a Supabase function.
- Inbound (Slack → Tasker, slash commands / create-from-message): MODERATE (a few days). Needs a real Slack App: OAuth, event subscriptions / slash commands pointing at a Supabase Edge Function endpoint, + Slack request-signature verification. Patterns already exist (claude.ai MCP OAuth2, GitHub OAuth).
- "Similar apps" (Linear, Notion, Discord, …) DON'T compose into one feature — each is its own OAuth+API. Long tail. Options: build GENERIC outbound webhooks + lean on Zapier/Make/n8n (one build covers many apps), OR hand-build only the 1-2 apps the audience asks for.
STRATEGIC NOTE: this is a web-app / TEAM feature (notifications, shared visibility) — fits the eventual paid/team tier, not the solo-dev-via-MCP wedge. Probably defer until the team tier is real.
