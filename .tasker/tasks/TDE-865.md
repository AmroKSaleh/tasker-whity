Settings displays GitHub as connected — green status dot plus a "Disconnect" button — but the stored credential is invalid. Every page that calls GitHub gets a 401.

Observed 2026-08-02 against https://smarttasksxdd.netlify.app:
- GET https://api.github.com/user -> 401, fired from /settings and from /dashboard/:slug
- Surfaces in the browser console as "Failed to load resource: the server responded with a status of 401"
- Settings still renders the connector as healthy (screenshot: Z:\Tasker\_check\shots\desktop.settings.png)

Two separate problems:
1. The token is expired/revoked and nothing refreshes or invalidates it. TDE-91 auto-attaches a PAT on GitHub login and TDE-75 uses the OAuth token — whichever path produced this credential has no expiry handling.
2. The UI reports a connection state it never verified. A connector that 401s should render as disconnected or errored, with a reconnect prompt — silently showing green means GitHub-dependent features (issue sync, push-to-GitHub) fail with no explanation.

Fix 2 regardless of 1: the health indicator should reflect an actual probe, not merely the presence of a stored token.
