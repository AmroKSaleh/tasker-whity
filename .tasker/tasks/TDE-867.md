With the theme set to always-dark (localStorage tasker-theme = "dark"), body background is correctly dark — rgb(22, 21, 27) — on every route. But the redesigned pages paint light/cream content surfaces over it, so only /settings actually reads as dark.

Measured 2026-08-02 across /settings, /home, /projects, /flows, /dashboard/:slug, /environments, /recycle-bin — identical body background on all seven, but the screenshots show /settings dark and the rest light (Z:\Tasker\_check\shots\desktop.*.png). Script: _check/theme.mjs.

So this is not "dark mode is broken" — the theme is applied at the root and the newer page surfaces simply hardcode light colors instead of reading theme tokens.

MAY BE INTENTIONAL. The Front Page / board redesign (TDE-350, TDE-352) and the palette work (TDE-353) may have deliberately committed to a single light look. Filed low priority as a question to settle, not a confirmed defect: either restore dark support on those pages, or drop the dark toggle so the setting stops promising something it does not deliver. The current state is the worst of both — a setting that appears to work but changes almost nothing.
