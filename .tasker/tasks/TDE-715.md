Make a task's milestones editable through .tasker/ files. Split out of the section+milestones push (2026-07-18) because reading the code revealed milestones are NOT a clean child table — they share storage with the seed system, so a naive round-trip risks clobbering seed checklists. Needs its own careful pass. Section create-by-reference shipped separately.

THE LANDMINE (why this isn't trivial): milestones are stored in `task_discussions.steps` + `checked_steps` — TWO PARALLEL POSITIONAL ARRAYS, not a child table. `steps` entries are strings OR objects with `.summary` and `.kind`. Critically, the SAME `steps` array also holds SEED checklist items (open_questions as kind="question", prerequisites as kind="prerequisite") and discussion steps. So milestones, seed questions, and seed prerequisites are INTERLEAVED in one array on seed tasks. Writes go through Postgres RPCs (append_milestone, set_milestone_checked, delete_milestone_at), not plain table writes.

CONSEQUENCE: a whole-list-replace of `milestones:` from a file (the simple rule we use elsewhere) would, on a SEED task, DESTROY the seed's open_questions/prerequisites and their kind tags. Must not happen.

WHAT ALREADY EXISTS (the easy half): local_format.ts serializeTaskFile ALREADY emits `milestones:\n  - { "text", "done" }` and parseTaskFile parses them into task.milestones. dbRowToTaskerTask (sync_core.ts) does NOT currently populate milestones, and buildLocalBundle doesn't fetch them — so pull simply omits them today. Emitting on pull = fetch task_discussions.steps/checked_steps, map the MILESTONE-kind (plain/no-kind) entries to {text,done}, populate dbRowToTaskerTask.

DESIGN TO SETTLE:
- Sync rule: match-by-text, position tiebreak, whole-list-replace — BUT scoped ONLY to milestone-kind entries; seed questions/prerequisites must be preserved untouched. So reconcile = "replace the milestone subset, leave kind-tagged seed items alone."
- Emit only for NORMAL tasks, or also surface seed checklist items read-only? (Recommend: emit milestones for all tasks; NEVER let flush write seed-kind items — those stay MCP-only.)
- Flush write path: call the RPCs (append/check/delete) to preserve the discussion structure + triggers, OR reconstruct steps/checked_steps arrays directly? RPCs are safer (respect existing invariants) but N calls; direct array write is 1 update but must perfectly preserve non-milestone entries + ordering.
- .sync.json hashing already covers task files, so no new bookkeeping — but changing a task file's milestones must re-stamp updated_at (LWW anchor) like any task edit.

POINTERS: list_milestones/add_milestone handlers (index.ts ~4439+) show the task_discussions.steps/checked_steps shape + the RPCs. Seed creation (create_task, ~3552-3579) shows how questions/prerequisites land in the same steps array with kind tags. dbRowToTaskerTask + serializeTaskFile already have the file shape. KB: "Local Mode: group create-by-reference" (the create pattern), TDE-534 umbrella.

NEXT STEP: decide the reconcile-scoped-to-milestone-kind approach + RPC-vs-direct write, then build. Verify LIVE against the throwaway copy, and TEST that flushing a SEED task's file does NOT touch its open_questions/prerequisites.
