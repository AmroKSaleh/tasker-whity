Replace the fly-in IntakePanel modal with a Conductor column docked permanently inside each connector page (scoped by `source`; start with Gmail). Decisions locked with user:

- Per-connector, NOT app-wide. Each connector owns its conductor so captures never mix across sources. Component is `<Conductor source="gmail" />`, reused per connector page via AppShell's rightRail slot (constant docked column, not an overlay).
- Three tabs = the intake_job lifecycle, left→right:
  • in-flight — pending|processing (agent reading/structuring; realtime "working" box)
  • parked — agent submitted result, NOT yet placed; the editable task proposals (current IntakePanel "ready" editor becomes the drill-in here)
  • placed — task CARDS for tasks imported from this connector. Renders real task cards (reuse existing card), click → task / project board. Show/hide DONE filter inside the tab (user toggles; provenance retained, not dropped).
- +Task feeds the conductor's in-flight tab instead of opening a modal.
- Parked items stay as intake_jobs until placement (no orphan tasks with null project_id).
- Rail icon badge: parked count per connector (e.g. "Gmail ③") so parked items aren't invisible when off the page.

Data-model work:
- New status flow: pending|processing (in-flight) → ready (parked) → imported (placed) + error. Update submit_intake_result to set 'ready' (was 'done'); importTasks to set 'imported'. Frontend treats legacy 'done' as parked.
- Task provenance: add tasks.intake_source + tasks.intake_job_id, set at import. Tab 2 queries tasks by intake_source.
