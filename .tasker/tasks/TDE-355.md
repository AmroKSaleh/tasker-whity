Second build step of Environments (TDE-308). Requires the 1/5 DB migration to be applied first.

All work in V2/supabase/functions/mcp/index.ts (single ~6,400-line edge function; tool definitions ~line 530+, handlers in the switch ~line 2160+).

Deliverables:
1. New tools: list_environments, create_environment, rename_environment, delete_environment (delete must reassign its projects to another environment — refuse to delete the last one).
2. create_project: accept optional environment_id; default to the user's active_environment_id from user_settings; error clearly if neither resolves.
3. list_projects: group or annotate output by Environment; optional environment_id filter; default remains ALL projects (the AI should see everything unless the caller filters).
4. __init_tasker_session (def ~line 1372): report the Environment list + the current active_environment_id as a default the AI may use.
5. Downstream tools (tasks, sections, flows, KB, IS) need NO change — they inherit Environment transitively via project_id.

Core principle (decided in TDE-308, do not reopen): the AI must NOT silently inherit an invisible active-Environment pointer. environment_id is always an explicit arg with the active one offered as a visible default via init. The web app owns pointer WRITES; MCP only reads it (a set_active_environment MCP tool is explicitly out of scope for v1).

Deploy per runbook: supabase functions deploy with --no-verify-jwt; never redeploy while a request is in flight (KB entry on this). MCP tool list is session-cached — restart the MCP connection to see new tools.
