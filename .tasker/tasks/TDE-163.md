RESOLVED (2026-06-09) — was NOT an auth/connection/load failure. Init always worked. The real issue: on a returning session (preferences already exist) the handler took the silent `status:ready` branch and returned prefs with NO questionnaire, so CC just loaded projects and moved on. User expected the settings surfaced on init.

Per original TDE-97 design this silent-after-first-time behavior was intentional. User changed the desired behavior. Agreed new behavior (chosen via options): "Summary + offer" — NOT a full questionnaire every session.

Fix (V2/supabase/functions/mcp/index.ts, case '__init_tasker_session'): the returning-session branch now returns settings_summary (friendly current values) + a presentation instruction telling the client to show a compact summary and offer "change settings", and to call __init_tasker_session with show_questionnaire:true when the user wants to review/adjust. First-time setup (no prefs) and the show_questionnaire:true review path are unchanged.

Verified live post-deploy: default init returns settings_summary+presentation; show_questionnaire:true returns review_setup with all 6 questions and current choices marked "(current choice)".
