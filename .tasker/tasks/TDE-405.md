Follow-up from TDE-404 (agents-use-Tasker-by-default). Gated on the Claude Code PLUGIN existing — do not start until Tasker is distributed as a CC plugin.

Goal: strongest possible "use Tasker by default" engagement signal on Claude Code, with zero incremental user setup. CC plugins can package hooks (hooks/hooks.json). Bundle a SessionStart hook that, when a repo/user has Tasker configured, auto-runs the Tasker init and surfaces the ready queue into the agent's context at session start — so the agent SEES real Tasker work without deciding to reach for it.

Why this is deferred (not done in TDE-404): as a standalone hook it needs per-machine install (settings.json + script), which leaks setup friction and undercuts "by default." A plugin removes that friction — installing Tasker installs the hook. So it only makes sense once the plugin ships.

Scope note: CC-only. The MCP serverInstructions active-routing rewrite (shipped in TDE-404) remains the portable floor covering Cursor/Windsurf; this hook is the CC-specific ceiling ON TOP of it, not a replacement.

Context: see KB "{mcp} (ai) Agents-use-Tasker-by-default — routing instruction rewrite; local-first rejected (TDE-404)". The A/B split still holds — the hook surfaces DURABLE work (Job B); it must not try to capture the native scratchpad (Job A).

Prereq: Tasker packaged/distributed as a Claude Code plugin.
