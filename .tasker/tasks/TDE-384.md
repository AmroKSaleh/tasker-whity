From Linear: agent signals include a human→agent "stop" — on receiving it "the agent must not perform any further actions — such as making code changes, updates, or additional API calls," then must confirm with a response/error activity.

Build the pull-shaped version: a server-side stop flag the human sets on a flow (or single task) from the inspector, with a reason. While set: run_flow, guide_flow, advance_guide, and complete/validate calls on that flow REFUSE to proceed and return the stop reason; the agent must acknowledge before anything else on that flow. Clearing the flag resumes exactly where things stood (guide_cursor unchanged).

Complements the quality gates rather than duplicating them: gates check QUALITY of outputs; stop checks INTENT — "human changed their mind mid-flow" currently has no mechanism, the agent just barrels on. Cheap to build (one flag + checks in the flow tools) and very on-wedge: the human-shared state includes the human's ability to halt it.

## Build spec — locked 2026-07-11 (my recommendation) — cheapest high-wedge win; buildable anytime (independent of 374)
- Add to flows (and optionally single tasks): `stop_requested bool`, `stop_reason text`, `stopped_at timestamptz`, settable from the inspector.
- Enforcement: while stop_requested, the flow tools — run_flow, guide_flow, advance_guide, and complete_task/validate on that flow — REFUSE and return the stop reason. The agent must acknowledge before doing anything else on that flow.
- Clearing the flag resumes exactly where things stood (guide_cursor unchanged).
- This is one flag + a guard at the top of each flow-tool handler. Complements the quality gates: gates check output QUALITY; stop checks human INTENT ("changed my mind mid-flow"), which today has no mechanism — the agent just barrels on.
Low effort, very on-wedge (human-shared state includes the human's power to halt it).
