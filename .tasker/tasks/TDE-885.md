Requested by the owner 2026-08-08, immediately after TDE-884 shipped cascade deletion. TDE-884 hard-deletes environments and orgs because neither has an is_deleted column; this adds one and makes the whole cascade reversible.

WHY SOFT DELETE SOLVES "RESTORE EXACTLY AS THEY WERE" ALMOST FOR FREE
Hard deletion destroys MEMBERSHIP, not just the container: projects.environment_id is ON DELETE SET NULL, so deleting an environment forgets which projects were in it, and no restore can reconstruct that. Soft deletion never nulls the pointer, so every FK still resolves and membership survives untouched. Same for environments.org_id. environment_grants also survive, where a hard delete cascades them away.

THE ONE THING SOFT DELETE DOES NOT SOLVE — WHY A CASCADE TOKEN IS NEEDED
If a project inside an environment was ALREADY in the recycle bin before the environment was deleted, restoring the environment must not resurrect it. Marking rows with a shared deleted_cascade_id at delete time makes restore exact: revive only what this cascade took, leave earlier deletions alone.

RESTORE MUST ALSO REVIVE ANCESTORS
Restoring a project whose environment is still deleted would leave it pointing at an invisible parent. So restoring any row revives its still-deleted ancestors too — otherwise "restored" can mean "unreachable".

⚠ THE REAL RISK IS THE READ SURFACE, NOT THE WRITE
This is TDE-882 repeating on two new tables. Every query reading environments or organizations must filter is_deleted or deleted rows reappear in the UI. Counted at filing: ~6 web SELECT sites (useEnvironments x2, refreshEnvironments, refreshOrganizations, the two contents helpers) and ~10 MCP environment sites (index.ts around 3840, 4079, 4085, 4105, 4118, 4134-4137, 4145, 4154-4156, 6764). The MCP has no organization reads at all — it exposes no org tooling.

PURGE ORDER MATTERS
The pg_cron job (migration 20260801153600) purges after 7 days and must be extended. Order has to be projects, then environments, then organizations — purging an org first would cascade its environments and null the environment_id of projects that had not been purged yet.
