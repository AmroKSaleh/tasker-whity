From Linear: get_issue returns a pre-formatted branchName so coding agents check out correctly-named branches; closing words in PR/commit text ("fixes/closes/resolves ABC-123") move the issue automatically — In Progress when the branch/commit is pushed, Done when merged to default; non-closing words ("refs", "part of") link without closing; a branch name merely containing the ID links it. Configured per-team under Workflows & automations.

Build: get_task returns a canonical branch_name (e.g. tde-123-slug, format configurable); GitHub integration parses magic words in PRs/commits → task state follows real code events. The twist that makes it OURS: if the task has review enabled, merge routes to needs-review instead of auto-done — the quality gate intercepts the automation (Linear just closes; we verify). Durable state that updates itself from actual work = "measure progress with actual work," enforced.

Cross-ref: TDE-150 (in-app push button), TDE-344 (verify-before-complete), TDE-348 (review card), existing github_sync_issues/github_push_* tools.
