The live public docs page at /docs/mcp/flows opens with "A **flow** is a chain of contract-linked tasks" — the exact definition the redefinition agenda retired (TDE-793…TDE-803; canonical write-up on TDE-792, directive already rewritten and deployed in TDE-808).

WHERE: V2/app/src/docs/contentMcp.js, the 'mcp/flows' key (around line 54). Routing confirms this is the served copy — App.jsx maps /docs/* to DocsPage, which imports NAV_MCP/PAGES_MCP from docs/contentMcp. There is a separate /docsV2 route backed by contentMcpV2.js which does NOT define a flows page, so contentMcp.js is the only public flows explanation that exists.

WHY THIS MATTERS MORE THAN THE DIRECTIVE DID: TDE-808 fixed guidance aimed at AGENTS. This one misleads PEOPLE, publicly, on the live Netlify site — and the docs are the front door for anyone arriving via the open-source push (TG-55/TG-77). Someone evaluating Tasker reads this page to learn what a flow is.

WHAT THE PAGE CURRENTLY GETS WRONG: it defines a flow as a contract-linked chain (contracts are now OPTIONAL — a gateless flow is still a flow); it states "each handoff carries two contracts" as though mandatory (gates belong only at SEAMS — handoffs the receiver will not re-derive); it presents the validation loop as the centrepiece (the independent judge is now a last resort, not the default enforcer); and it says nothing about the scale floor, which is now the property that actually separates a flow from ordered tasks.

Pull the replacement wording from the canonical definition on TDE-792 and from the rewritten directive in ASSISTANT_DIRECTIVES (V2/supabase/functions/mcp/index.ts) so all three agree.

NOT AUDITED YET, worth checking in the same pass: ContractEditor.jsx and FlowTaskPanel.jsx may carry copy that assumes contracts are mandatory.

Deploy note: this is a FRONTEND change — Netlify (npx netlify-cli deploy --prod --dir=dist), a different deploy path from the MCP edge function.
