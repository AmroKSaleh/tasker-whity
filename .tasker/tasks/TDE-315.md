BLOCKS round 2 (the task "Run round 2..."). Goal: fix the validator so it can be trusted, then prove it on known-correct code — otherwise round 2's B-vs-C result is uninterpretable (a weak result couldn't be told apart from "validator is broken").

BACKGROUND (round 1 finding): In the contract-gating experiment Round 1, Arm B (full = contract + independent validator + revision loop) reached the SAME 100% as Arm C (spec-only) but burned ~2.6 revisions, and 4/5 B trials hit the 3-revision cap — the validator kept flagging "issues" on code that already passed all 27 oracle tests (false positives; it never said PASS). Root cause: the validator prompt is adversarial/"assume the code is WRONG and hunt for every violation" (a FAIL-prior framing). That over-rejects.

WHAT TO DO:
1. Rewrite the validator prompt to CONFORMANCE-checking, with PASS reachable: "Check the candidate against the spec. Return pass=true if it conforms. Only flag CONCRETE spec violations (a specific rule it breaks) — never style, naming, or hypothetical concerns. Do not request changes that don't map to a spec rule."
2. The validator lives in TWO places — recalibrate both: (a) the API-path harness `runner.py` -> validate(); (b) the subagent-path workflow validator agent prompt (the round-1 workflow script: V2/.../workflows/scripts/contract-gating-experiment-wf_93911d55-8e5.js, or re-author it for round 2). Round 2 uses the subagent path.

FREE VERIFICATION (the gate): run the calibrated validator against the FIVE Arm-C solutions from round 1 — they are known to score 100% on the oracle. Raw candidates are saved at V2/experiments/contract-gating/round1_candidates.json (arm=="C" entries; note the code may be HTML-escaped — html.unescape it, see score_subagent_output.py:clean_code). The calibrated validator MUST return pass=true on all 5. If it still flags any, keep tuning the prompt until clean. Only then is round 2 unblocked.
