GOAL/WHY: During bootstrap (the coherence pass in bootstrap_advance), the agent challenges the plan for coherence — e.g. "why defer subscriptions to Phase 2?". The challenge AND how it resolved are decision provenance: they define design choices and influences for work that comes later. Today they only survive if the agent happens to hand-write a KB entry (e.g. the "why subscriptions deferred" entry from the Handmade Candles test). Make capturing them structured/automatic so the rationale isn't dependent on the agent remembering to write prose.

CURRENT STATE: the coherence pass runs inside the bootstrap flow; resolutions become ad-hoc, optional KB entries. Nothing structured records the challenge→resolution pair against the Foundation.

OPEN DESIGN QUESTIONS (settle BEFORE building — this is the prerequisite to resolving this task):
- WHERE it lives: a `coherence_decisions` array on project.context/Foundation JSON, vs. a dedicated typed KB category, vs. a new column. Leaning toward Foundation JSON so get_project_foundation can surface it.
- SHAPE: e.g. { challenge, resolution, scope_item?, ts }. Should each decision link to the scope_out/assumption item it concerns?
- WHO writes it: the bootstrap_advance coherence phase automatically, or an explicit MCP call the agent makes during the pass.
- HOW surfaced: include in get_project_foundation output and/or the project-context block injected into get_task, so future agents inherit the "why" automatically.

NEXT STEP: a short design decision on storage + shape, then implement in the bootstrap coherence phase and surface it in the Foundation. (Consistent with how the seed-checklist merge was handled: converge on the design first, then build — do not build this blind.)
