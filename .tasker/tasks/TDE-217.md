Root cause identified and fixed: the `flow_step` column (added in migration 20260605150000_add_flow_step.sql) was never applied to production. resolveTask's SELECT includes `flow_id, flow_step` — when either column is missing, PostgREST returns a column-not-exist error, maybeSingle() gets null, and resolveTask silently returns null for ALL task lookups (both short IDs and UUIDs). list_tasks and create_task work because they don't select these columns. Fix: ran `npx supabase db push` which applied the missing migration. resolveTask now works correctly.
