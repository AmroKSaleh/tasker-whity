## Measurement 2 — post-TDE-371 session floor (2026-08-07)

TDE-371 fixed the per-call cost (get_task context tiering). This measures what is left: the SESSION-START cost, which TDE-371 did not touch.

Sampled on a trivial read-only request ("show me the tasks inside Core App") in a cold Claude Code session. Estimated from character counts of the tool results (~3.6-3.9 chars/token for dense JSON, ~4.2 for prose) — no exact counter was available, so treat as ±10%.

Cost of that one request, ~8,100 tokens total:
- __init_tasker_session — ~23,000 chars → ~6,000 tokens (74%)
- ToolSearch, 4 tool schemas loaded — ~4,500 chars → ~1,250 tokens (15%)
- list_sections, 13 sections — ~750 chars → ~200 tokens
- list_tasks, 13 tasks — ~2,350 chars → ~650 tokens (8%)

The part that actually answered the question was 8% of the spend.

### Finding 1 — the init directives are an unconditional charge

The directives array is ~21,000 chars / 22 entries, shipped in full to every session regardless of what the session does. On the sampled request, zero of them applied.

The real cost is NOT dollars. It sits in the cached prefix, so after turn one it is a cache read at ~10% of input price, and on the owner's subscription that is ~$0. The costs that matter:
- Attention. Every irrelevant directive is a rule the agent must decide not to follow, and instruction-following degrades as that pile grows. The 2,400-char flow-definition directive is pure noise in a read-only session AND competes with the directives that do apply.
- Third-party users on metered API clients pay it as a real per-session line item.

Do NOT solve this by cutting directives. They are load-bearing — the flow definition exists because agents were inventing their own, and that error costs far more than 6k tokens to clean up. Solve it by making the charge CONDITIONAL.

Proposed tiering (same first-touch-then-pointer pattern already shipped for get_task):
- Always-on core: attention-first, durable-work routing, lifecycle, dedupe, ambiguity, no-sycophancy, self-contained task context — ~1,250 tokens
- Flows bundle (flow definition, build/run/name, gating, validation independence, check rules, revision loop, step-list-open) — ~2,450 tokens — load on first touch of build_new_flow / run_flow / validate_output
- Local Mode bracket — ~630 — load only when the project actually has Local Mode on (the server already knows this)
- Autonomous loop — ~420 · Verify-before-complete — ~315 · Relay mode — ~290 (load on relay_context) · Bootstrap — ~240

Target: a read-only session pays ~1,250 instead of ~6,000. Roughly a 75% cut to the session floor.

### Finding 2 — tool-surface area is the harder half

~190 Tasker tool names sit in the agent's context as a deferred-tool list before any tool is called: roughly 1,000-1,200 tokens, permanently, plus a schema fetch (~300 tokens each) every time one is needed. This is structural surface area, not prose that can be trimmed, and no amount of directive tiering touches it. Likely needs tool consolidation or namespacing to move.

Neither finding is built. This task remains reference-only; if either is actioned it should get its own task.
