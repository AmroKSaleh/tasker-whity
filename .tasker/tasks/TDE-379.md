Build (inverted — no server-side AI): (a) create_task and submit_intake_result return similar existing tasks (title/detail match) so the CALLING agent dedupes before creating; (b) a merge_task_as_duplicate MCP verb: transfer milestones/notes/links to the canonical task, close the dup with provenance and a distinct duplicate outcome (not plain done).

Live evidence we have the disease: ~11 identical "Expose Waqtak to the outside world" tasks sitting in TDE right now, created across sessions. Duplicate defense is core durable-multi-agent-state hygiene: agents across sessions MUST converge on one task, not spawn parallel copies.
