GOAL: Let Tasker create native Google Docs and Google Sheets (not just upload raw text files) and drop them into the same task/flow Drive subfolder that drive_upload_file already uses (Tasker/ProjectName/FlowShortId/, or standalone/ for non-flow tasks), recording the Drive file ID on the task output.

WHY: Today drive_upload_file only accepts content MIME types (text/plain, text/markdown, etc.). It uploads a file as-is; it does NOT create Google-native documents. Confirmed 2026-06-25: calling drive_upload_file with mime_type "application/vnd.google-apps.document" fails with "Invalid MIME type provided for the uploaded content". So when a user wants an editable Google Doc artifact (e.g., an article draft handed to a human for review/audit in a content flow), the only result is a .md/.txt file. The current workaround is manual: open the uploaded .md in Drive via "Open with > Google Docs". Users expect Tasker to produce the editable Doc directly.

WHAT TO BUILD:
- Support creating Google-native files (at least Docs and Sheets) via the Drive API's convert-on-import: upload the media with its real source MIME (text/markdown or text/html for Docs; text/csv for Sheets) AND set the file metadata mimeType to the target Google-apps type (application/vnd.google-apps.document / application/vnd.google-apps.spreadsheet) so Drive performs the conversion. The current code is passing the google-apps type as the *upload content* type, which Drive rejects; that is the bug to fix.
- Surface it either as a new param on drive_upload_file (e.g. google_native: true, or target_type: "doc" | "sheet" | "file") or a dedicated tool (e.g. drive_create_doc). Keep the same folder-placement + task-linking behavior (task_id -> project/flow subfolder + record file ID on task output) that drive_upload_file already has.
- Decide input format: Docs convert cleanly from HTML or Markdown (headings, bold, links render); Sheets from CSV. Document which input formats map to which target types.

ACCEPTANCE: A single tool call creates an EDITABLE native Google Doc (and a Google Sheet) from text/markdown/HTML (and CSV) content, lands it in the task's flow subfolder, links it to the task, and the file opens as a real Doc/Sheet (not a raw .md/.csv file). Verify by reading it back / opening it.

POINTERS: Lives in the Tasker MCP server alongside drive_upload_file / drive_read_file / drive_list_files. Note: store_artifact also has an upload_to_drive option, which may want the same native-Doc capability. The Drive folder-creation path already works (Tasker/Project/Flow subfolders are created on upload).

ORIGIN: Surfaced while running the WCP-CCF article-production flow in the Waqtak Content Production project, where the EN draft needed to be an editable Google Doc for the human audit gate.
