Google Calendar in the web app uses the LEGACY browser GIS flow (googleCalendar.js, gcal_* short-lived access token, NO refresh token) — which is why it keeps showing "Session expired / Reconnect". The new Google services (Drive/Gmail/Tasks) use the google.js refresh-token flow (google_* tokens + server-side auto-refresh, TDE-245), so they persist.

GOAL: move Calendar onto the same refresh-token flow so it stops disconnecting.

CATCH (why this isn't trivial): the refresh token lives server-side; the browser can't safely refresh. Today the web app calls the Calendar API directly from the browser with the short-lived token. To use the persistent connection, Calendar API calls need a server token path — either (a) a small edge endpoint that returns a fresh access token to the client (reusing loadGoogleAccessToken), or (b) proxy the Calendar reads/writes through an edge function. Decide (a) vs (b).

Then: add the calendar scope to GOOGLE_SCOPES, fold Calendar into the shared Google connection (it becomes the 4th google-kind connector instead of the separate 'gcal' kind), and retire googleCalendar.js / gcal_* columns. Follow-up to the connectors framework (903c312).
