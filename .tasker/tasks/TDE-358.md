Part of the Environments series (parent design TDE-308; hierarchy Tasker → Environments → Projects). Depends on 1/5 (TDE-354, DB) and 2/5 (TDE-355, MCP environment tools). This is the final part — the create/manage surface + project reassignment that 3/5 (TDE-356, switcher + board scoping) does not cover.

GOAL: give the user a way to CRUD Environments (create, rename, reorder by sort_order, delete) and to assign/move a project to a different Environment from the web app. 3/5 builds the switcher to CHANGE the active env; this builds the surface to MANAGE the set of envs and where projects live.

KEY DECISIONS (from TDE-308):
- Single-user only; environments = { id, user_id, name, sort_order, created_at }.
- A Default Environment exists (backfilled in 1/5) and holds all pre-existing projects.
- Project↔Environment assignment happens at creation (2/5 create_project takes environment_id) AND via a move/reassign control added here.

OPEN QUESTIONS to settle during build:
- Delete behavior for a NON-EMPTY environment: block with a warning vs auto-reassign its projects to Default. (Lean: reassign to Default, never orphan projects.)
- Where the manage surface lives: a dedicated Settings section vs a "Manage environments…" affordance hanging off the rail switcher from 3/5.

NEXT STEP: build the manage-environments UI (list + create/rename/reorder/delete) wired to the 2/5 MCP env tools, plus a "move project to environment" control on the project (board header or project card menu).
