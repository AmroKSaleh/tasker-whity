The "Add Task" button disappears when the tasks in a section card extend beyond the height of the section. I can scroll to the bottom of the section, but the "Add Task" button is hidden.

═══════════ INVESTIGATION LOG (2026-06-10) — NOT FIXED, still in_progress ═══════════

SYMPTOM: In sections whose tasks overflow the column height (e.g. Core App, GTM, B2B & Teams), scrolling the column to the bottom does NOT reveal the "+ Add task" button. Short (non-overflowing) sections show it fine. Desktop, reproduced in Chrome.

CONFIRMED via live console diagnostics (user ran snippets in Chrome DevTools):
- The column scroll body (.col-body) IS correctly bounded and scrollable: clientH=731, scrollH up to ~2986, overflowY=auto. overflow scroll works.
- Container chain is fully height-bounded: col-body 731 ⊂ column 775 ⊂ cols-scroll 775 ⊂ div.h-full 919 ⊂ main 919 = viewport innerHeight 919.
- col-body top=188, bottom=919 → its bottom edge sits at the EXACT bottom of the browser viewport.
- Core App and GTM have NO groups, so the ungrouped "+ Add task" (ProjectBoard.jsx ~line 205) IS the last child — not buried mid-column.
- Deepest elements in a tall column are real task cards (no phantom/absolute element inflating scrollHeight).
- The "Search" bar visible at the very bottom of the user's screenshots is the WINDOWS 11 TASKBAR, not an app element. No app-level fixed bottom bar exists on desktop (only md:hidden mobile NavigationRail).

LEADING THEORY: board is locked to viewport height (h-screen) with internal per-column scroll, so a column's bottom is pinned to the very bottom of the viewport — right where the OS taskbar sits. The last item (Add task) parks under that strip and there is no page scroll to lift it up. (NOT fully confirmed — see open questions.)

ATTEMPTS (all built + deployed to Netlify; NONE resolved it):
1. Replaced col-body `pb-12` with a real flex spacer `.col-body::after { height:1.5rem }` (rationale: browsers clip a flex-column scroll container's padding-bottom from the scrollable area). → no effect.
2. Added `min-h-0` to the 3 column divs (normal SectionColumn + 2 focus-mode columns) (rationale: flex items' default min-height:auto let columns grow past the scroll container). → DID make col-body properly bounded/scrollable (verified), but visible symptom unchanged.
3. Bumped `.col-body::after` spacer to 4.5rem (72px) to lift the last item clear of the taskbar. → still same.

RULED OUT: padding-clip-only; height-cascade break; phantom/absolute element; buried-mid-column; app-level bottom bar.

OPEN QUESTIONS FOR NEXT SESSION (decisive diagnostic to run first):
After `cb.scrollTop = cb.scrollHeight`, report the Add-task button's getBoundingClientRect().bottom vs window.innerHeight:
  - If button bottom < innerHeight → it IS within the viewport (so the taskbar is overlapping the browser; fix = keep board content out of the bottom safe strip, e.g. give the board/cols a bottom margin so columns don't reach absolute viewport bottom; or make 72px spacer actually take effect / verify it deployed).
  - If button bottom > innerHeight → it's below the viewport, i.e. col-body isn't actually scrolling to its end under the user's input (scroll-interaction issue — hidden scrollbar + wheel stopping short, or dnd-kit intercept).
Also verify `.col-body::after` is actually applied + sized in the loaded build (getComputedStyle(cb,'::after').height) — earlier spacer changes had no visible effect, which is suspicious; the deployed CSS may not be loading, or ::after isn't counted as a flex item in scroll height in this browser.
Possible real fixes once confirmed: give the whole board a bottom safe-area / margin so columns end above the taskbar; OR make the Add-task affordance a sticky footer; OR allow the column content past the taskbar via a larger guaranteed-scrollable spacer that is verified to register.
