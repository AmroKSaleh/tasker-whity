The two CHEAP wins from the "add group/section/milestone functionality" push (2026-07-18), split from the manifest work (seed 497f93ac) which needs new format + design. These two reuse patterns already proven this session — no new file format.

1. SECTION CREATE-BY-REFERENCE: mirror the group create-by-reference just shipped (TDE-581). An unknown `section:` slug on a task currently warns + keeps the hub's section (applyFlush slugToSectionId ~line 821). Change: unknown slug → CREATE the section (name = slug verbatim, slug-is-name → guaranteed round-trip), register in maps so sibling tasks in the same flush reuse it, bind the task. Report in a new created_sections[] on the flush response (+ note). Sections have no parent, so simpler than groups (no cross-section guard). Section sort_order = max existing + 1.

2. MILESTONES IN FILES: milestones are a child list under a task, currently hub-only (NOT emitted on pull, NOT read on flush). The serializer ALREADY has the shape (local_format.ts serializeTaskFile emits `milestones:\n  - { "text": ..., "done": ... }`, and parseTaskFile parses it into task.milestones) — it's just not wired into the DB<->file bundle. Wire it: (a) dbRowToTaskerTask must include milestones from the hub (check the milestones table/RPC); (b) buildLocalBundle already serializes whatever dbRowToTaskerTask returns, so emitting is mostly making the DB read include them; (c) applyFlush must diff the file's milestones against the hub and reconcile. SYNC RULE (decided): match-by-text, position as tiebreak, WHOLE-LIST-REPLACE on flush (simplest; milestones low-stakes; whole-list-replace = LWW on the whole list, acceptable). Milestones have no stable id in files.

POINTERS: applyFlush + resolveGroupForTask (the create-by-ref pattern to mirror) in index.ts; slugToSectionId ~821; dbRowToTaskerTask + serializeTaskFile in sync_core.ts/local_format.ts; how milestones are stored hub-side (list_milestones/add_milestone/complete_milestone tools + the milestones table). KB: "Local Mode: group create-by-reference via flush (TDE-581, slug-is-name)" for the create pattern + why slug-is-name. Verify LIVE (applyFlush has no mock-sb harness) against the throwaway copy, clean artifacts after.
