## Objective
Expose section analysis as MCP tools so Claude Code can provide AI-powered insights without in-app inference calls.

## Tools to Add

### 1. `analyze_section` (Data Analysis)
Returns structured analysis of a section without AI inference.

**Input:**
- `section_id` (required) or derive from context
- `project_id` (required) — for ownership verification

**Output:** Plain text structured breakdown
```
Section: Core App (project: Tasker Development / TDE)

Task Summary:
- Total: 12 tasks
- Done: 3
- In Progress: 4
- Pending: 5

Group Balance:
- Group: UI Components (5 tasks, 42%)
- Group: State Management (4 tasks, 33%)
- Group: API Integration (3 tasks, 25%)

Blockers:
- TDE-45 (pending) blocks: TDE-46, TDE-47
- TDE-32 (in_progress) blocks: TDE-48

Stale Tasks:
- TDE-12 (pending for 8 days)
- TDE-15 (pending for 12 days)
```

**Purpose:** Claude Code reads this and can provide analysis like "you have 2 old tasks" or "group balance is skewed toward UI"

### 2. `section_insights` (AI-Powered Analysis)
AI-powered diagnostic of a section (what's wrong/missing/lacking).

**Input:**
- `section_id` (required)
- `project_id` (required)
- Optional: `analysis_type` ('quick' | 'detailed') — quick gives 1-2 key findings, detailed gives full diagnosis

**Output:** Plain text AI analysis
```
## Section Analysis: Core App

**What's Working:**
- Balanced group distribution (UI 42%, State 33%, API 25%)
- 33% of tasks in progress (healthy velocity signal)

**What Needs Attention:**
- 2 tasks blocking 4 others (TDE-45 is a critical blocker)
- 2 tasks pending > 7 days (TDE-12, TDE-15 may need review or removal)
- Pending task ratio is 42% (high relative to in-progress)

**Suggested Actions:**
- Prioritize TDE-45 to unblock downstream work
- Review TDE-12 & TDE-15: still relevant or should they be deleted?
- Consider moving 1 pending task to in-progress to increase velocity

**Quick Health Score:** 6/10 (good structure, but blockers and stale tasks pulling down)
```

**Purpose:** Claude Code reads this and understands section health, can suggest next steps

## Implementation Details

### Location
`V2/supabase/functions/mcp/index.ts` — add to TOOLS array and runTool switch

### Data Gathering for analyze_section
```
1. Get section: name, project_id, project.prefix
2. Get all tasks in section
3. Calculate: total, done, in_progress, pending
4. Get all groups in section
5. For each group: count tasks, calculate %
6. Find blockers: tasks with related_task dependencies
7. Find stale: pending tasks with age > 7 days
8. Format as structured text
```

### Data Gathering for section_insights
```
1. Call analyze_section to get structured data
2. Build prompt with section context
3. Call Claude API (Opus 4.7) with system prompt:
   "You are analyzing a section of a task management project. 
    Provide insights on: What's working, what needs attention, suggested actions.
    Keep it concise and actionable. Rate the section health 1-10."
4. Return AI response
```

### Ownership Verification
Both tools must verify user owns the project:
- `resolveProject(sb, userId, project_id)` → verify ownership
- Then access section/tasks data
