Deferred "later stage" half of TDE-324. TDE-324 shipped task relay with a FREE-TEXT recipient recorded inside `relay_context` (e.g. "to: Sara (backend)") — no DB link, no validation. The endgame described on TDE-324: give the MCP access to TEAM MEMBERS (with well-defined roles, duties, responsibilities, capabilities stored in the DB) so relay can route/assign a task to the right member automatically.

Why this is a seed (blocked + underspecified): it depends on multi-tenancy / membership work that is discussed but NOT built. Per memory [[design_worlds_environments_multilogin]], there's an UNRESOLVED FORK between (A) Supabase identity-linking (simple multi-email-login) and (B) membership + RLS (foundational, real team members with roles). Team auto-routing needs (B)-style member records. Can't spec the routing until that identity/membership foundation is chosen and built.

When unblocked: design the team-member schema (roles/duties/capabilities), expose members to the MCP, and upgrade relay's free-text recipient into a real member reference + optional auto-assignment. The free-text recipient in `relay_context` is the forward-compatible stepping stone.

Pointers: relay impl in V2/supabase/functions/mcp/index.ts (search `relay_context`, RELAY MODE directive). Multi-login memory: design_worlds_environments_multilogin (TDE task 247b626c).
