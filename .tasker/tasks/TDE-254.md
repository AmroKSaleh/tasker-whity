Follow-up to TDE-184. The dynamic KB now WRITES automatically (agents create KB entries on task completion via the universal IS rule), but project-KB READS are still on-demand only.

THE GAP: get_task auto-injects the project Instruction Set (always) and the Flow KB (for flow tasks only) — but NEVER the project KB (project_knowledge). A normal non-flow task only sees accumulated project knowledge if the agent explicitly calls get_knowledge_base. So the KB grows but doesn't reliably feed back into future work.

Reference: get_task injects project IS at V2/supabase/functions/mcp/index.ts ~L1901-1927 and Flow KB at ~L1929-1938; project KB is pull-only.

OPTIONS TO DECIDE BETWEEN:
1. Auto-inject project KB into get_task (like flow KB) — simplest, but bloats every task payload as the KB grows; needs a cap or relevance filter.
2. Handshake/IS directive telling agents to call get_knowledge_base at the start of relevant work — cheap on tokens, but relies on agent compliance.
3. Hybrid — auto-inject a lightweight index (titles only) into get_task; agent pulls full content via get_knowledge_base when a title looks relevant.

Recommended starting point: option 3 (titles index + on-demand full pull) — bounded token cost, still surfaces the KB's existence on every task.

Related: should pair with the earlier decision on whether dynamic-KB behavior lives as a universal handshake directive (all projects/users) vs the current TDE-only IS entry.
