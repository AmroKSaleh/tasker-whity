WEAKNESS (concrete bug found 2026-06-05): a producer's `output.ledger` is a single list and `validated_against` holds one target — so validating the same producer against TWO consumers (fan-out) overwrites the first result (last-write-wins). The ledger only reflects the most recent handoff.

FIX: store the ledger PER OUTGOING EDGE (keyed by consumer task), so fan-out producers keep a complete validation history for each downstream handoff. Prerequisite for a trustworthy audit trail (#validation-audit-trail).
