From Linear: every agent engagement creates an AgentSession on the issue with states pending/active/awaitingInput/error/complete/stale — state is DERIVED from the last emitted activity, never hand-managed. Agents emit typed AgentActivities (thought/action/elicitation/response/error) that render as a rich, inspectable thread; activities are immutable "frozen-in-time snapshots" (unlike editable comments).

Build (pull-shaped for Tasker): a per-task session object + append_session_activity MCP tool with a small typed vocabulary (progress / action / question / result), lifecycle state derived from the last entry, rendered on the task in the web inspector as the durable "what did the agent do" record. Front Page hook: strip of sessions awaiting input.

This is the single biggest gap vs Linear and pure wedge material — durable, human-inspectable agent state across sessions. Strongly overlaps TDE-362 (record session context inside Tasker): this task is the concrete Linear-informed design for it; building this likely closes TDE-362. Related: TDE-348 (needs-review card state).

## Build spec — locked 2026-07-11 (design pass, pre-migration)

Decisions resolved this session:

**Immutability:** activities are append-only — no UPDATE/DELETE row, no edit tool, enforced by RLS. The ledger is the raw provenance truth; the clean human-facing summary stays in task detail / project updates. Do not "tidy" the ledger.

**Schema (two tables):**
- agent_sessions — one per contiguous agent engagement on a task: (id, task_id, actor, opened_at, last_activity_at). `actor` is the SAME field TDE-375 threads through writes — create the column here, populate it fully in 375.
- agent_activities — append-only: (id, session_id, type, body, created_at). type ∈ progress | action | question | result | error.

**Derived state (READ-TIME, no stored column, no sweeper needed for correctness):**
- last activity = question → awaiting_input
- last activity = error → error
- session explicitly closed / task done → complete
- last activity within threshold → active
- else (older than threshold, not complete) → stale (threshold configurable; v1 default ~24h)
Front Page "awaiting-input" strip = the same query filtered to awaiting_input. A background sweeper is only a later optimization to precompute stale on large boards — NOT required for v1.

**MCP surface:** append_session_activity(task_id, type, body) — opens a session lazily if none active. get_task folds in the recent session thread. Cross-task attention pull is TDE-383, not this task.

**Why this is the spine:** agent_sessions is the render substrate for TDE-375 (actor attribution hangs on the session), TDE-382 (review narrative renders against a session), TDE-383 (attention = query for sessions awaiting_input). Build this first; those three assume it exists.
