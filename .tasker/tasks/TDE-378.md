From Linear: their MCP ships ~42 coarse tools and STILL gets publicly flamed as the biggest context hog in a 4-server stack (~12.8k tokens of tool definitions always loaded). Their countermeasures: merged create+update into one save_issue ("fewer calls, less latency"), changelog-level commitment to "reduced token usage through better tool documentation," a paste-any-URL resolver collapsing N lookup tools, Relay cursor pagination (default 50, has_more), and a uniform filter grammar incl. relative durations ("P2W") on every list endpoint.

Build: Tasker carries ~150 MCP tools — our most exposed flank. (a) tool census + token measurement of the loaded surface; (b) consolidation plan: merge create/update pairs (save_task etc.), audit every tool description as a token budget; (c) cursor pagination with small defaults + has_more on list_* tools; (d) small shared filter vocabulary (status/section/updated_since with relative durations) instead of ad-hoc params per tool; (e) a resolve-short-ID/URL tool collapsing lookups.

Direct extension of TDE-371 (context tiering) and the TDE-372 report — tiering fixed response size; this fixes REQUEST-SIDE surface. Token economy is now a public battleground; this is the enabling condition for the wedge (cheap injection).
