Follow-up to TDE-324 (task relay, MCP-first). TDE-324 added a `relay_context` text column on `tasks` and renders it in the MCP `get_task` output behind a `[Recording context for the task]` marker. But the WEB APP does not render it yet — so today only an AI assignee picking the task up via MCP sees the relay hand-off notes; a HUMAN teammate viewing the task in the web app sees nothing.

Goal: render the relay layer in the web task detail panel so human assignees get the same benefit. When `tasks.relay_context` is non-null, show a visually distinct block (the `[Recording context for the task]` marker + the curated notes) above/near the normal detail/Context. Read-only display is enough for v1; authoring relay from the web UI is a separate, larger piece (relay is currently authored via the AI/MCP).

Pointers:
- Column: `tasks.relay_context` (migration V2/supabase/migrations/20260630120000_add_task_relay_context.sql).
- MCP render reference: get_task block in V2/supabase/functions/mcp/index.ts (search `relay_context` / `[Recording context for the task]`).
- Web task view components live under V2/app/src (task detail panel). Match the editorial design system; bordered container per the button/style rules.

Next step: find the task-detail component, add a conditional relay block bound to relay_context, deploy frontend to Netlify.
