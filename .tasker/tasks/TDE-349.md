From the board UX review (see TDE-346 for full framework). Three header/legibility fixes on the project board (ProjectBoard.jsx header block, ~line 580-660):

1. GROUP AI GOVERNANCE: Context / KB / IS are the AI's operating boundaries — keep them persistently visible (do NOT bury behind a gear; ambient presence reinforces "the AI is governed"), but they currently sit at the same visual weight and spacing as the view-toggles (Blueprint / Focus). Separate them into a distinct, quietly-labeled cluster (e.g. an "AI" group label) so the two kinds of control don't read as one undifferentiated row. Also spell out or tooltip the acronyms KB (Knowledge Base) and IS (Instruction Set) — they're insider jargon a new user can't parse.

2. COUNT LEGEND: the section-header "x/y" count is an unlabeled riddle (done/total? pending/total?). Add a tooltip or label clarifying it (it's done/total, matching the top-level 151/225).

3. HIDDEN SECTIONS: right rail shows "SECTIONS 11" but only 6 columns render (the rest are hidden by the default section filter). Surface this state — e.g. "(5 hidden)" or a filter indicator — so the user isn't silently misled about missing sections.

Frontend-only. Note: some sections are intentionally hidden by default (GTM/monetization/B2B) per the owner's filtering rule — this task is about making the hidden COUNT visible, not un-hiding them.

--- OUTCOME (built + deployed) ---
Done: (1) grouped the AI-governance controls under a quiet mono "AI" label separated from the Blueprint/Focus view-toggles, and added tooltips spelling out Context / KB (Knowledge Base) / IS (Instruction Set). (2) Added a "Completed / total tasks" tooltip to the section-header x/y count (Kicker atom).

DROPPED item 3 (surface hidden-sections) — MISDIAGNOSIS. The board does NOT hide sections. ProjectBoard.jsx renders ALL sections via enrichedSections.map inside an overflow-x-auto container (line ~696), so "11 sections, 6 visible" just means the other 5 are scrolled off horizontally. The original "hidden state" finding wrongly imported the ASSISTANT-side section-filtering habit (hiding GTM/monetization when listing tasks in chat) into a UI critique where it doesn't apply. No fix needed.
