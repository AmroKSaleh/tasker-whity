WHY (measured, this session 2026-07-18): the per-task ⚖ governance footer stamps the FULL Instruction Set into EVERY task file on pull. For a realistic "read 10 tasks, edit 3" agent session this made LOCAL cost ~12,700 ingest tokens vs ONLINE (tiered get_task) ~5,800 — i.e. local is ~2.2x MORE expensive, and 65% of local ingest is the repeated IS footer (~820 tokens x N files). This BREAKS the core premise that "local = cheaper." Removing the per-task footer and grounding once-per-session drops local ingest to ~4,500 tokens — local then BEATS online AND gains an offline KB. This restructure is the FOUNDATION the whole "expand local mode toward web-app parity" roadmap rests on (user's goal: cheap + offline + git-native local projects). Do this BEFORE TDE-581 and other local-parity work — they edit the same files.

DECISION (agreed with user, do exactly this):
1. New file [prefix]-instruction-set.md — the full project IS in ONE file. REMOVE the IS from per-task governance footers entirely. Governance becomes "agent reads the IS file once per session" (same model the online MCP already uses via context tiering). TRADEOFF accepted: governance-by-convention, not governance-in-every-task.
2. New file [prefix]-foundation.md — goal/why/scope/success/risks (tiny, read once).
3. New kb/ folder — one .md per KB entry (filename from title + a title header + the body). Mirrored to disk ON PULL, READ-ONLY (offline-READABLE; KB authoring stays an MCP ceremony — no KB-body LWW in this cut). Agent reads only the 2-3 bodies it needs, so usage stays cheap.
4. context.md slims to: Foundation pointer + KB index (titles) + how-to-fetch note pointing at the kb/ folder. NO separate kb.md (context.md is already the guaranteed once-per-session read).

TRADEOFFS accepted: (a) governance-by-convention vs in-every-task; (b) pulls now carry all KB bodies = bigger wire payload (bytes over the network, NOT agent tokens — acceptable); (c) local KB read-only for now.

BLAST RADIUS (core sync code — highest in the system): local_format.ts (serializer), buildLocalBundle (the pull writer, index.ts ~631-690), and the withGovernance/footer injection (index.ts ~651-665, ~751-760). Update the two node tests (local_format.test.node.ts, local_sync.test.node.ts — run under `node --experimental-strip-types`, must exit 0). Update the DESKTOP VIEWER (V2/desktop/renderer/app.js) — it currently strips a ⚖ GOVERNANCE footer that will no longer exist; harmless but clean it, and it can now show IS/Foundation from the new files.

GOTCHAS (from KB "Local Mode v1 SHIPPED" TDE-F2): local_format.ts is erasable TS (no enums/namespaces or node --strip-types breaks); keep the updated_at touch-trigger behavior intact; .sync.json hashes cover every written file, so new files (instruction-set.md, foundation.md, kb/*) must be in the hash set or they'll look perpetually changed. Design doc: V2/docs/local-first-design.md.
