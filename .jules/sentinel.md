## 2025-02-18 - Sanitizing URL Params in Markdown Components Renders
**Vulnerability:** Reflected Cross-Site Scripting (XSS) in dynamic wildcard routes (`/docs/*` and `/docsV2/*`). The dynamic path wildcard parameter `slug` was concatenated into a fallback Markdown string, parsed via `marked.parse()`, and injected directly into the DOM using `dangerouslySetInnerHTML`. Because `marked` compiles raw HTML block/inline elements and permits breakout of markdown inline code blocks via backticks, malicious URL parameters successfully bypassed escaping and ran arbitrary JavaScript.
**Learning:** Dynamic parameter input in routes should never be directly concatenated into Markdown templates or raw HTML templates without proper escaping. Even if the dynamic parameter is enclosed in backticks (e.g., code blocks), an attacker can break out using matching backticks and then supply raw HTML/JS script payloads.
**Prevention:** Always sanitize any URL-controlled or dynamic user-provided parameters using a strict HTML and Markdown-characters escape function (such as converting `<`, `>`, `&`, `"`, `'`, and `` ` `` to their HTML entity equivalents) before constructing the Markdown template or feeding it to a renderer.
