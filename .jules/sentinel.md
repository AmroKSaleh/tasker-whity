## 2026-07-30 - OAuth Authorization Code Interception and Open Redirect Vulnerability
**Vulnerability:** The OAuth client authorization page `app/src/pages/OAuthAuthorizePage.jsx` accepted any `client_id` and `redirect_uri` from query parameters without verifying them against registered records in the database (`oauth_clients`). This allowed unauthorized clients to request access and permitted arbitrary redirect domains (Open Redirect), opening the door to authorization code theft and phishing attacks.
**Learning:** Even if API endpoints validate authorization codes and token exchanges on the backend, the frontend authorization consent page must strictly validate `client_id` and `redirect_uri` on load. Allowing unvalidated URLs to trigger "Allow/Deny" flows allows attackers to intercept authorization codes or trick users into redirecting to malicious external sites.
**Prevention:** Always validate client registration and verify that the requested `redirect_uri` exists in the whitelist of registered URIs for that client before rendering the consent screen. Block any action (including Deny redirects) if validation fails, displaying only a safe in-app fallback.
